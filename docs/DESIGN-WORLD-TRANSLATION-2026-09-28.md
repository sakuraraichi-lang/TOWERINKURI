# 既存のゲームを「エクスメントマキナ」の世界観へ翻訳する（検討・2026-09-28）

企画書：`docs/WORLD-BIBLE-v1.0.md`（ユーザー作・原文）。以下「§n」はその節。
**これは検討。まだ何も実装していない。**企画書 §29「世界観のために新しいシステムを足さない」に従い、
**今あるものをどう読み替えるか**だけを並べた。

---

## 0. 結論

- **ゲームの骨格は企画書とすでに一致している。**「5ウェーブ → 章 → 転生 → 恒久成長 → さらに深く」（§0）は今の進行そのまま。システムは足さなくてよい
- **いちばん大きな財産は「盤がもともと六角＝ハニカム」なこと。**§9〜10「ハニカムの奥に基板が見えてくる」は、章ごとに盤の絵の層を足すだけで作れる。盤の絵は章ごとに1枚に焼いて使い回しているので（`Render.boardImage`）、**重さはほぼ増えない**
- 色（黒地に橙・琥珀・赤）もすでに §18 の方向。音と絵をその場で生成する作り（WebAudio・Canvas）も、FM音源風の曲や低解像度風の絵を作る土台になる
- **企画書と食い違っているのは、主に絵と音**：いつも出ている走査線（§19 に反する）、つやのある丸い玉の敵（§13）、生き物らしい血飛沫（§13）、BGMが1種類（§24）、タイトル画面・転生の演出・レジェンダリーの特別演出が無い（§19・§20・§28）

## 3. 盤の「露出」（世界観の背骨）

§9・§10・§31：「壊れていく」のではなく「最初からあった中身が見えてくる」。**遊びのルールは変えない。**

今の盤の絵は、章ごとに1回だけ描いて使い回している（`Render.boardImage`：壁を塊で塗る → 通路の縁の橙の光 → 床）。
**壁の塊の中に、章に応じた層を焼き込む**だけで作れる。毎フレームの描画は増えない。

| 段 | 章（案） | 壁の中に見えるもの |
|---|---|---|
| 1 | 第1〜4章 | 今のまま。ハニカムの壁だけ |
| 2 | 第5〜10章 | ところどころ継ぎ目から配線・LEDの点がのぞく |
| 3 | 第11〜19章 | 基板の配線（直角に折れる銅色の線・端子・部品）が壁の中に通る |
| 4 | 第20〜30章 | 基板がはっきり見え、ハニカムは上に被さった装甲の板に見える |
| 5 | 第31章〜（アセンション） | 配線の上をデータの光が流れる。壁の中にシステムの文字（16進・ログ）が見える |

- 動くもの（段5のデータの流れ・LEDの点滅）は、すでにある盤の動きの層（`Render.boardAnim`）に少しだけ足す。量は測りながら決める（§30 重くしない）
- 盤は全員同じ30章で固定なので、**どの章でどの段が見えるかも全員同じ**になる
- 章の区切りは、今の幕（導入・最初の壁・恒久層・自動化・特化・決着・果て。画面には出ていない）に合わせてもよい

## 4. 敵・武器・撃破の絵

**敵（§13）**：侵入プログラムに「昔のゲームの敵キャラ」の皮。
- 今の8種は性質がはっきりしているので、形を当てやすい：
  ふつう（grunt）・速い（swift）・硬い（tank）・盾（shield）・群れ（swarm）・再生（regen）・分裂（split）・入れ子（nest）・ボス
- 1体ずつの絵は種類×色×大きさで1回だけ描いて使い回している（`enemySprite`）ので、**凝った絵にしても毎フレームの重さは変わらない**
- 低解像度風（大きなドットの輪郭）× 滑らかな動き・光（§22・§25）

**武器（§14）**：今の砲台の絵（`turretSprite`・`turret`）は、台座＋砲身の形。名前と役割はそのまま、形の言葉だけを統一する。

**撃破（§16）**：「パンッと弾け飛ぶ」。今の血飛沫を、**敵の色のドット片・データ片が弾ける**形に変える案。
向きや量（侵攻方向と逆に飛ぶ）は、ユーザーが以前に決めたものなのでそのまま使える。

**ダメージ数字（§17・§23）**：⚙に「ダメージ数字を出す」のオン・オフを足す（ライフのバーと同じ形）。
出すときの動きは、文字の出現・拡散・消失をモーションとして作る。

## 5. 演出（3つ・どれもゲームを止めない長さで）

§30「長い演出でゲームを止めない・リザルトを遅くしない」ので、**どれも短く、タップで飛ばせる**ことを条件にする。

1. **タイトル**：CRT の画面が点いて、ゲームの世界へ入る（§19「現実とゲームをつなぐ窓」）。読み込みを増やさない（絵は Canvas で描く）
2. **転生**（§28）：確認のあと、視点が引いて、CRT テレビと PC のある部屋 → テレビにニュースや広告の断片（AI競争・AIによるハッキング・AIの求人…）→ ゲームの画面へ戻り、今の REBIRTH と報酬へ。
   ニュースの文は短い見出しだけ。**ニュースを読むための画面は作らない**（§29）
3. **レジェンダリーの開封**（§20）：放送停止の画面 → グリッチ → 虹。今の開封（帯を剥がすとカードが飛び出す）のレジェンダリーのときだけ差し込む。
   演出の見本はすでに `?packdemo=legendary` で出せるので、作りながら確かめやすい

**警告表示（§11）**：「EXTERNAL ATTACK DETECTED」「VIRUS DETECTED」「外部から攻撃を受けています！」など。
操作も進行も関係なく、壁の中や画面の奥を一瞬流れる。出す瞬間の候補：ボスのウェーブ、漏れたとき、深い章ほど時々。

## 6. 音（§24）

今は `Audio.bgmStart` が同じ和音をゆっくり回すだけ（1種類）。
- **準備中（戦闘前）**：喫茶店のようなゆったりした曲（柔らかい鍵盤の和音）
- **戦闘中**：PC-8801 の FM 音源を思わせる、電子的なアーケード曲（矩形波・FMの金属的な音色・速い分散和音）
- 準備完了を押した瞬間に切り替わる ＝ 「日常 → ゲーム → 電子世界」の切り替え
- どちらも WebAudio でその場で作れる（素材ファイルを持たない決まりのまま）

## 8. UI の統一（いちばん大きい）

§21「すべて同じデザイン言語から」・§22「汎用図形を使わない」。
今の画面は、ホーム・下のタブ・パネル（スキル・装備・パック・図鑑・転生）・結果・3択・置く武器の枠・調整パネル・⚙が、それぞれ別々に育ってきた。
**最初に「デザイン言語のルーツ」を1つ決めてから**、部品（ボタン・札・帯・数値の枠）を作り直して全画面に当てる順番がよい。
アイコンはすでに自前の絵（`Icons`）なので、そこは言葉をそろえるだけで済む。

1. **小さく安く効くもの**：走査線を常時から外す／タイトルとロゴの名前／ボスのカットインに警告の文字／ダメージ数字のオン・オフ
2. **盤の露出**（§3）：世界観の背骨。1枚に焼く絵なので重さに響かない
3. **敵の絵と撃破の弾け方**（§4）
4. **BGM 2種**（§6）
5. **演出**：レジェンダリー → 転生 → タイトル（§5）
6. **UI の統一**（§8）：デザイン言語を決めてから

どの段でも、スマホで重くなっていないか（フレーム時間）を測ってから出す。
