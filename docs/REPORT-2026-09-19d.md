## 0. まず訂正 — 武器は壁の上にしか置けない

「武器を置ける場所は**壁の外側と中だけ**」とのご指摘のとおり、私は**逆に作っていました**。試作では敵が通る地面に置けるようになっていました。直しました。

| | 直す前（誤り） | 直したあと |
|---|---|---|
| 置ける場所 | 敵が通る地面 | **壁（地形）の上だけ。外周の壁も含む** |
| 弾 | 壁に当たると消える | **壁を越えて飛ぶ**（壁の上から撃つため） |
| 外周 | 1セル | **2セルの厚み**（外側にも置けるように） |

実測で確認：初期配置が全部壁の上／通れる地面をタップしても置けない／光る場所が全部壁。

あわせて、**壁が多すぎて敵が細い筋になっていた**ので島を0.62倍にしました。
**壁31% / 通れる69%** になり、600体で画面が埋まります。

## 1. 扇の向きは手動のみ。バーで操作

「絶対手動。戦闘前の準備フェーズで行うところだから自動はNG」とのご指示どおり、**自動旋回を完全に削除**しました。

ユニットを選ぶと、パネルに**2本のバー**が出ます。

| バー | 範囲 | 効果 |
|---|---|---|
| **向き** | 0〜360° | 触ったその場で扇が回る |
| **射界** | 武器ごとの最小〜最大 | 広げると守備範囲が増え、**集弾率が下がる**（同時に表示） |

つまみは24pxの丸にしてあり、指で掴めます。

## 2. 配置の流れを作り替えた

「地面をタップして置く、という動作をまずやめよう」とのご指示どおりに変えました。

```
  ① 上の「武器」から選ぶ
        ↓
  ② 盤面が少し暗くなり、置ける場所（壁の上）が光る
        ↓
  ③ タップで配置
        ↓
  ④ そのまま調整パネル → 向き・射界をバーで決める
```

- 置いてあるものをタップ → 同じパネル。「**配置を変える**」でまた光って、移動先を選べます
- 「やめる」でいつでも抜けられます
- **画面を邪魔しない**よう、調整パネルが出ている間は下のツールを引っ込めます
- 置けない場所をタップしても**何も起きません**（赤い輪で知らせるだけ。武器が増える誤爆は消えました）

## 5. 既存ゲームへの取り込みを開始

**第一歩として、検証済みの「敵同士の押し合い」を本体に入れました。**（バケット方式＝お気に入りとのことだったので、まずこれから）

### 実測

| 敵数 | 押し合いなし | 押し合いあり |
|---|---|---|
| 400体 | 0.09ms／重なり **96%** | 0.31ms／重なり **4%** |
| 900体 | 0.18ms／重なり **97%** | 1.15ms／重なり **5%** |

- 900体を15秒走らせて「**一度も前進しなかった敵は0体**」
- 測定器で `st3` を通しで回して**5ウェーブ突破**（94秒・撃破254・漏れ1）
- 本体を起動して600体を描画し、**通路いっぱいに詰まった帯**になることを確認

### 調整ノブは `balance.js` に集約（方針14）

| ノブ | 意味 |
|---|---|
| `crowdOn` | **false にすれば以前とまったく同じ挙動に戻せる** |
| `crowdCell` | 押し合いを見る格子（24） |
| `crowdPush` | 重なりのどれだけを押し戻すか（0.5） |
| `crowdCap` | 押し戻しの上限。**前進が押し返しに負けないよう上限を置く**（永久停止の防止） |

### バランス値は1つも変えていません

`enemyHpBase 19` / `stageHpMul 1.35` / `waveCountMax 600` は元のままです。

**※ このあと取り込み②で、スナイパーだけは変えました**（`pierce` 1→3 / `target` strongest→dense）。これは「弱いから強くした」のではなく**役割を立てるため**で、敵HPやウェーブ数、報酬には触れていません。**押し合いと貫通で難易度は動きますが、再調整は取り込みが一段落してからまとめて行います。**

## 5-2. 取り込み② — スナイパーを貫通役にする（完了）

調査で分かっていた3つの原因のうち2つを潰しました（3つ目「敵がすり抜けて直線に並ばない」は取り込み①で解決済み）。

| | 前 | 後 |
|---|---|---|
| 狙う相手 | `strongest`（最も硬い＝後方のタンク） | **`dense`（敵が濃いほう）** |
| 貫通 | 1 | **3** |
| 貫いた表示 | **無し**（カウンタを減らすだけ） | **軌跡を残し、当たった数だけ太くする** |

**実測:** 500体の群れにスナイパー1基を向けて1200フレーム回し、**軌跡483本すべてが複数貫通、最大4体**を同時に抜きました。通し（コールドスタート1回目）では 訓練場が5W到達で力尽き、螺旋と広間は突破。コンソールエラー0。

## 5-3. 取り込み③ — 配置UIを試作の流れに（完了）

**「なぞって向ける」をやめました。**

| | 前 | 後 |
|---|---|---|
| 置く | 地面をタップ（どこに置けるか不明） | **武器を選ぶ → 盤面が暗転し、置ける地面が光る → タップ** |
| 向き | 盤面をなぞる | **バー（0〜359°）** |
| 射界 | ◀狭／広▶ ボタン | **バー（0〜100%、集弾率も同時表示）** |
| 動かす | 撤去 → 置き直し（向きと射界が消える） | **「配置を変える」→ 光る → タップ。向きと射界はそのまま運ぶ** |

`state.js` に `moveUnit` を足しました。

**実測**（本体を起動、コンソールエラー0）：① 選んでタップで増えて選択状態になる ② バー2本が効き、射界を最大にすると集弾45%まで下がる ③ 移動しても**向きと射界が残る**・増えない ④ 通路をタップしても増えない。座標の往復（タイル→画面→タイル）の一致も確認。

> **なお、これを「Aの判断待ち」に積んでいたのは私の誤りでした。** 既存の `buildable` は元から「地面（壁側）」を指しており、**配置UIの流れはマップの形に依存しません。** マップ改修を待つ理由はありませんでした。

## 5-4. 取り込み④ — 倒したらコインが飛ぶ（完了）

撃破しても HUD の数字が静かに増えるだけで、**報酬を得た実感がありませんでした**。倒した場所から画面上のコイン表示へ、小さな◈が0.5秒で飛ぶようにしました。ボスは大きめ。**同時に飛ぶ数は26個まで**にして、敵が多いときに盤面が見えなくなるのを防いでいます。

**実測:** 1200フレームでコイン演出 延べ900・同時最大4（上限26に余裕）。貫通の軌跡52本と同時に出ても破綻しません。
