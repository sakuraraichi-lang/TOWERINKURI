## 1. 「更新されてない」件 — 配信は最新でした

実測で調べました。

| 調べたこと | 結果 |
|---|---|
| `relics.js` が配信されているか | **されている**（HTTP 200） |
| CSSの主色 | `--acc:#ff8a1f`（**新しい橙**） |

つまり **Vercel は正しく更新されていました。**

### 原因はエッジのキャッシュでした

HTMLの応答ヘッダを見ると `x-vercel-cache: HIT` / `age: 746` で、
**12分前のHTMLが配られていました。** `must-revalidate` はブラウザ向けの指示で、
Vercel の CDN 側には効いていませんでした。

### 直したこと（2つ）

**① HTMLだけキャッシュさせない**

`vercel.json` で、HTML（`/` と `/index.html`、`/proto` も）に
`no-store, max-age=0, s-maxage=0` を付けました。
実測で `age: 5` まで下がっています。

**② 版を画面に出しました**

ホーム右上に **`0920g`** と小さく出ます。
次に「更新されてないかも」と思ったら、**ここの文字を教えてください。**
違っていれば端末のキャッシュ、合っていれば私の実装の問題だと、その場で切り分けられます。

### それでも古いものが出るときは

iPhoneで**ホーム画面に追加**している場合、そのアイコンから開いたものは
特にしつこくキャッシュが残ります。その時は

1. アイコンから開いているアプリを**タスクから完全に終了**する
2. それでも駄目なら、**Safariで直接** `https://towerinkuri.vercel.app/` を開く
3. 版が `0920g` になっているか右上を見る

## 2. スキップを入れました（`8f3c5f8`）

ご指示の「**何も失わなくて良い。ただ解放タイミングは慎重に**」のとおりにしました。

### 失うものはありません

| | スキップで得るもの |
|---|---|
| コイン | **前に自分で突破したときの最高額**をそのまま |
| 初回突破の報酬 | **出る**（カード・パック） |
| 完璧クリア | **一度でも完璧にしていれば、その記録どおり引き継ぐ** |
| ミッション | **判定される** |

### 代わりに解放を慎重にしました

| 条件 | 理由 |
|---|---|
| **転生を1回以上している** | 初周は全部自分で遊んでほしい |
| そのステージを**通算3回以上**突破している | 1回では手応えを覚えていない |
| **まだ突破していないステージは対象外** | 記録が無いので自動的にそうなる |
| 1周につき1ステージ1回まで | 手で突破するのと同じ |

通算の突破回数・最高コイン・完璧の記録は**転生でも消えません**。

### ボタンの出方

- **条件を満たすまでは出しません**（押せないボタンを置きっぱなしにしない）
- あと少しで解放されるときだけ、灰色で「**あと 2 回、自分で突破すると使えます**」
- 満たすと橙で「**スキップ ◈ 1.50K**」

**実測：** 押すとコイン +1500・突破 +1・ミサイルポッド獲得・パック +8、
次のステージへ自動で送られ、同じステージは2度押せません。

## 3. 【訂正】「時間の6割は敵を待っているだけ」は、言い方が間違っていました

前回こう書きました。

> 時間の6割は、敵が湧くのを待っているだけの時間

**これは正確ではありません。** 正しくは：

> **ウェーブの長さは、湧きのスケジュールで決まる。**
> 最後の1体が湧くまでウェーブは終われないので、火力を上げても短くならない。
> **その間ずっと戦闘は起きています。**「何もない空白」ではありません。

### そのため、案A も案B も入れていません

| | 結果 |
|---|---|
| **案B**（倍速を湧きにも掛ける） | **すでにそうなっていました。** `Main.loop` が `Combat.update` を `Game.speed` 回まわすので、湧きにも倍速が掛かります |
| **案A**（敵がいないとき湧きを早める） | 入れて測ったら**効果が誤差**（1周 19.5→20.4分／待ち率 65→67%）。湧き間隔が0.16秒なので、**盤面が空になる瞬間がほぼ無く、早める対象が存在しませんでした**。入れずに戻しました |

**根拠の無い調整ノブは残さない**ようにしています。

### ついでに、周回の長さの見え方も訂正します

測定器の「1周 19分」は**ゲーム内時間**です。
**プレイヤーは倍速で遊べます**（×1〜×3、転生後は×4）。

| 倍速 | 実際にかかる時間 |
|---|---|
| ×1 | 約19分 |
| ×3 | **約6分** |
| ×4（転生後） | **約5分** |

「周回が長い」問題は、思っていたより小さいかもしれません。
**実機で1周回してみて、体感の長さを教えてください。**

### では何が1周の長さを決めているか［実測］

| 変えたもの | 1周 |
|---|---|
| 火力 ×1 → ×10⁴⁰ | 19.3 → 10.1分（**1.9倍が上限**） |
| 湧き間隔 0.16 → 0.06秒 | 19.8 → 15.1分（**1.3倍**） |
| 敵がいないとき早める | 19.5 → 20.4分（**効果なし**） |

**一番効くのは「負ける回数」**です。永続カードが減らすのはここで、
実測で 8回 → 5回になっています。

## 4. 実機2000体で60fps、ありがとうございます

**設計書で最優先リスクに挙げていた「実機の描画負荷」が消えました。**

これで敵数の設計に上限を設ける理由が無くなりました。
ご指摘のとおり、**大群は後半・動画向けの絵**として扱い、
序盤は少数のままにします。1面1ウェーブから大量にする必要はありません。
