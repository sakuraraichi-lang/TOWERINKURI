## 1. 実測：何が壊れているか

### 1-1. こちらの伸びが、敵の伸びと噛み合っていない【確定】

敵の伸びは**毎ステージきっかり ×5.01** で固定です（`enemyHpGrowth^5 × stageHpMul`）。
それに対してこちらの伸びはバラバラでした。

| ステージ | 敵HP | 敵の伸び | こちらの力 | **こちらの伸び** | 追加設置 | 合計Lv |
|---|---|---|---|---|---|---|
| 訓練場 | 54 | — | 1.6 | — | 0 | 40 |
| 螺旋 | 272 | ×5.01 | 6.9 | **×4.25** | +1.33 | 148 |
| 広間 | 1,363 | ×5.01 | 16.8 | **×2.44** | +2.50 | 225 |
| 二面作戦 | 6,834 | ×5.01 | 210.9 | **×12.56** | +3.33 | 456 |
| 三叉 | 34,255 | ×5.01 | 379.0 | **×1.80** | +3.33 | 501 |

※「こちらの力」＝ 6カテゴリの火力倍率の平均 × 設置枠の増え方

読み取れること：

- **敵は等速、こちらは階段。** ×2.44 の面は苦しく、×12.56 の面は溶ける
- **二面作戦で一気に12.5倍。** ここで壊れる。敵の2.5倍の速さで伸びている
- **追加設置は3面目でほぼ上限**（+2.5 / 上限+4）。ご指摘のとおり早すぎます

### 1-2. コインに重みが無い【確定】

| ステージ | そのステージの稼ぎ | 残高 | **次の1段の値段** | 残高は次の1段の何倍 |
|---|---|---|---|---|
| 訓練場 | 866 | 2,102 | 30 | **70倍** |
| 螺旋 | 46,233 | 67,042 | 34 | **1,972倍** |
| 広間 | 327,382 | 394,423 | 55 | **7,171倍** |
| 二面作戦 | 7,268,541 | 9,603,216 | 55 | **174,604倍** |
| 三叉 | 33,533,318 | 43,136,534 | 55 | **784,301倍** |

**1面目の終わりで既に70倍持っています。** 2面目以降は「買う／買わない」という判断が
そもそも発生していません。「まとめて購入」を押すだけの画面になっています。

原因は**収入と支出の伸び方が違う**ことです。

- 収入 … 敵の数 × 1体あたりコイン。**ステージごとに ×40〜70** で伸びる
- 支出 … `cost0 × costG^Lv`。costG は 1.31〜2.6 なので、**1段ごとに ×1.3 程度**

段を1つ買っても値段は1.3倍にしかならないのに、収入は1ステージで40倍になる。
**この差がそのまま「重みの無さ」です。**

### 1-3. ツリーが浅い【確定】

| | |
|---|---|
| ノード数 | 27（うち上限無しが6） |
| **1周で上限まで買い切ったノード** | **21個中11個** |
| 1周終わりの合計レベル | 464〜501 |

**上限のあるノードの半分以上が、1周で打ち止め**になっています。
上限に達したもの：`regen:10 short_unit:4 mid_unit:4 long_crit:20 long_unit:4
area_size:25 area_unit:4 target_unit:4 picks:3 choices:3 pack:12`

### 1-4. カードが早すぎる【確定】

| | |
|---|---|
| 1周で開けたパック | 10個 |
| 1周で集まった種類 | **84種中 32種（38%）** |

**1周で4割近く集まります。** 転生で消えないので、2周目には引くものが減ります。

### 1-5. 設置台数と、湧き位置【確定＋観察】

設置台数ノードは6カテゴリぶんあり、**どれも上限まで7,264コイン**です。
2面目の終わりに67,042コイン持っているので、**2〜3面目に6種類すべて買い切れます。**

そして、設置台数は他の強化と性質が違います。

| | |
|---|---|
| 火力 ×1.18 のノード | その武器のダメージだけが増える |
| **設置台数 +1** | **火力も、カバー範囲も、漏れにくさも同時に増える。しかも他の全強化と掛け算になる** |

**湧き位置への設置**は、私が今回入れた指定攻撃の仕様が直接の原因です。
着弾円は**射線を持たず、射程内ならどこにでも置ける**ようにしたので、
「敵が必ず、常に、最大密度でいる1点」＝湧き口が、無条件の最適解になりました。
設計の穴です。

## 2. 直し方の案

**ここから先は案です。数値は暫定で、実測して決め直します。**

### 案1 — 敵の伸びに、こちらの伸びを合わせる

**確定させたい原則：**

> **1ステージ進むと、敵は ×5 強くなる。こちらも ×5 前後しか強くなれない。**

いま ×12.56 の面があるのが問題なので、**こちらの伸びに天井を作る**のではなく、
**伸びの源を数え直して均す**方向で考えます。

やること（暫定）：

1. どのステージで何倍伸びるかを、いまの実測表を基準線として持つ
2. 各ノードの `costG`（1段ごとの値上がり）を、**収入の伸びと同じ次数**に上げる
3. 1周ごとに再測し、×5.01 からの外れが ±30% に収まるまで詰める

**数値はまだ書きません。** costG をいくつにするかは、収入曲線を測ってからです。

### 案2 — コインに重みを戻す

いまは「収入 ×40／段の値上がり ×1.3」なので、どうやっても追いつきません。
**段の値上がりを、収入と同じ速さにします。**

| | 今 | 案（暫定） |
|---|---|---|
| costG | 1.31〜2.6 | **1周で上限に届かない値まで上げる** |
| 上限 | 多くが4〜25 | **主要ノードは上限を外し、値段で止める** |

**「上限で止める」のをやめて「値段で止める」**のが要点です。
そうすると「どれを伸ばすか」が毎周の判断になり、ツリーが深くなります（案3と同じ話）。

### 案3 — ツリーを深くする

**ノードを増やすのではなく、1本を長くする**ほうが先だと考えています。
理由：27ノードのうち11個が1周で打ち止めなので、**枝の数ではなく丈が足りていない。**

| | |
|---|---|
| **上限を外す** | 火力・射程・レートは上限無しにして、値段だけで止める |
| **上限を残す** | 設置台数・選択肢数・パック数（＝**増えすぎると設計が壊れるもの**） |

### 案4 — 設置台数を「早期に買い切れないもの」にする【一番効く】

いまは 7,264コインで上限まで行けます。ここを2つ変えます。

| | 案（暫定） |
|---|---|
| **値段** | costG 2.6 → もっと急に。**1周で1〜2段しか買えない**額に |
| **解放** | **ステージ突破で解放段数が増える**。コインでは前借りできない |

**2つ目が本命です。** コインは余るので値段だけでは止まりません。
「その段を買う権利」をステージ進行に紐づければ、**お金では飛び越えられなくなります。**

> 設置枠は、**踏破したステージ数**でしか増えない。コインは「その枠を埋める」ために使う。

これは自動化の設計書で決めた規則1（自分の手でやったことだけ肩代わりする）と同じ形で、
**「進行でしか買えないもの」と「お金で買えるもの」を分ける**という一本の規則になります。

### 案5 — 湧き位置への設置を止める

**私が入れた穴なので、直します。**案は3つ。どれを採るか伺いたいです。

| | 案 | 中身 | 副作用 |
|---|---|---|---|
| **A** | **湧き口に安全圏を置く** | 湧き口から一定距離の中には着弾円を置けない | 単純。ただし「線を引いただけ」で理屈が弱い |
| **B** | **湧きたての敵を無敵にする** | 出現後1〜2秒は当たらない | 全武器に効く。湧き口張り付きが全部無意味になる |
| **C** | **コアに近いほど報酬が増える** | 手前で倒すほどコインが増える | 止める場所に意味が生まれる。**私の推し** |

**C を推す理由：**禁止ではなく、**別の場所に置く理由を作る**ほうです。
A と B は「そこに置くな」ですが、C は「奥で倒したほうが儲かる」なので、
プレイヤーが自分で置き場所を選ぶ形になります。A と C は併用できます。

### 案6 — カードの入手ペースを落とす

1周で38%は多すぎます。ただし**単純に減らすと、引く楽しみも減ります。**

| | 案（暫定） |
|---|---|
| **プールを増やす** | いま84種。**分母を増やす**のが素直（デッキの設計と同時にやる） |
| **重複に意味を持たせる** | 同じカードが出たら**そのカードのランクが上がる**。ダブりが無駄にならない |

**2つ目を推します。** パックの数を減らさずに、集まりきるまでの距離を伸ばせます。

## 3. デッキシステム

> そろそろデッキシステムも真面目に組むべきだ

デッキタブは今、**枠だけで中身がありません。** ここで何を決めるべきかを整理します。

### 3-1. いま「デッキ」という言葉が指しているもの

現状、カードには3つの入り方があり、**どれもデッキではありません。**

| | どこで | いつ | 選べるか |
|---|---|---|---|
| 武器カード | 編成タブ | 出撃前 | **選べる**（4枠） |
| 強化カード | ウェーブ間の3択 | 戦闘中 | **引いたものから選ぶ** |
| 遺物 | 遺物パック | 転生後 | 選べない |

つまり **「戦闘中に何が出るか」をプレイヤーが決められません。** ここが空白です。

### 3-2. 提案する定義

> **デッキ＝ウェーブ間の3択に「出てほしいカード」を、あらかじめ選んでおく箱。**

| | |
|---|---|
| **何を入れるか** | 所持している強化カード（`kind:'mod'` と `'synergy'`） |
| **枠** | 暫定。ステージ進行で増える（案4と同じ規則） |
| **効果** | デッキに入れたカードは3択に**出やすくなる**。入れていなくても出る |
| **入れない選択** | デッキが空なら今と同じ（全部から等確率） |

**「出やすくする」で止めて、「デッキのものしか出ない」にはしません。** 理由：

- 完全指定にすると、**毎回同じ3択**になってローグライトではなくなる
- 引きの偶然は残したまま、**自分のビルドへ寄せられる**のがちょうどいい

### 3-3. デッキが解く問題

| 今の問題 | デッキが解く形 |
|---|---|
| 84種のうち32種を持っていても、**欲しい1枚が来ない** | 寄せられる |
| シナジー（2武器の組み合わせ）を**狙えない** | 組みたいシナジーをデッキに入れて狙う |
| **カードが余る**（案6） | 余ったカードに「デッキに入れる／入れない」という使い道ができる |

### 3-4. 決めていただきたいこと

| | |
|---|---|
| **1** | 「出やすくする」でよいか。それとも「デッキのものしか出ない」完全指定にするか |
| **2** | デッキ枠を何で増やすか（ステージ突破／転生／コイン） |
| **3** | デッキは転生で消えるか（**私の案：消えない。カードが消えないので** ） |
