## 2. 作り直すべきコアシステム

**「システム」として作り直しが要るのは1つだけです。**

### 入力・配置の層（新規 `src/input.js` 約150行）

今の構造の問題は、**ジェスチャが1つしかないこと**です。

| 操作 | 現状 | 問題 |
|---|---|---|
| 置く | トレイで武器を選ぶ → 盤面をタップ | 21pxのマスを指で狙う |
| 向ける | 盤面をドラッグ | **移動に使えるジェスチャが残っていない** |
| 動かす | **無い**（撤去→再設置の2手） | 煩雑 |
| 撤去 | 選択 → 撤去ボタン | — |

**作り直す設計:**

```
タップ           … ユニットを選ぶ／選択解除
ドラッグ（本体から）… つかんで移動。離すと確定
ドラッグ（外周リングから）… 向きを変える
選択中のピンチ    … 射界の開閉
長押し           … 撤去の確認
```

**選択中のユニットの周りにリングを描く**ことで、「本体＝移動」「リング＝回転」を指の位置だけで区別します。ボタンを増やさずに操作を3つに分けられます。

これは既存コードの改修では収まらないので、**`bindPlacement`（92行）を捨てて新規に書きます。**

## 3. 【重要】実測で判明した制約 — 敵数の上限は下げざるを得ない

> **【撤回】この節の「敵数を220体へ」という結論は誤りでした。**
> 素朴な衝突方式1つしか測っていなかったためです。3方式を実測したところ、
> 密度グリッド方式（O(n)）なら**3000体でもスマホ想定8.6ms**で収まります。
> さらに、**本当の制約はCPUではなくマップの幅**でした（900体は今のマップに物理的に入りません）。
> 現在有効な設計は [PLAN-PROTO-2026-09-19.md](PLAN-PROTO-2026-09-19.md) です。


衝突処理を**その場で試作して実測しました**（リポジトリのコードは変更していません）。

| 同時に居る敵 | 現状の1フレーム | 衝突あり | スマホ想定（PCの6倍遅い） | 判定 |
|---|---|---|---|---|
| 60体 | 0.14ms | 0.07ms | 0.4ms | 余裕 |
| 120体 | 0.09ms | 0.31ms | 1.9ms | 余裕 |
| **200体** | 0.05ms | **0.41ms** | **2.4ms** | **余裕** |
| 400体 | 0.10ms | 1.23ms | 7.4ms | ぎりぎり |
| **900体（現状の上限）** | 0.25ms | **5.96ms** | **35.7ms** | **60fps不可（28fps相当）** |

**コストは敵数に対して直線ではなく、密集するほど跳ね上がります**（近傍が増えるため）。900体では衝突処理だけで**現在の戦闘処理全体の24倍**かかります。

### これは妥協ではなく、設計の改善です

現在の `waveCountMax: 600` / `enemyCap: 900` は、**「敵がすり抜ける」前提で成立していた数字**です。すり抜けるから600体を同じ線の上に置けました。

**衝突を入れるなら、敵は「少なく・硬く・大きく」すべきです。** 600体がすり抜けて1本の線になるより、150体が詰まって団子になるほうが、タワーディフェンスとして正しく、そのほうが範囲攻撃と貫通の価値も出ます。

**提案：`enemyCap` 900 → 220、`waveCountMax` 600 → 200。** 減らしたぶんは敵1体のHPに乗せます。

## 8. 肥大化させず、実プレイ可能に到達する手順

**各段階で必ず「遊べる状態」を保ちます。** 途中で止めても遊べる形にしておくのが、肥大化を防ぐ唯一の方法です。

| 段 | やること | 時間 | **終わった時点で遊べるか** |
|---|---|---|---|
| **0** | `enemyCap` 900→220、`waveCountMax` 600→200、減らしたぶんHPへ | 20分 | ○ 敵が減って見やすくなる |
| **1** | **敵の衝突（grunt 1種）** | 60分 | ○ 敵が密集する |
| **2** | **スナイパーを貫通役に**（`pierce` 3 / `target` dense） | 20分 | ○ 貫通が刺さる |
| **3** | **貫通ビーム＋コインが飛ぶ演出** | 60分 | ○ **ここで「倒して気持ちいい」が成立** |
| **4** | swift / tank を戻して衝突を確認 | 30分 | ○ |
| — | **ここで一度スマホで遊んでいただく。合わなければ1〜3を捨てても損失は2.5時間** | | |
| **5** | **自由配置**（座標ベース化＋旧セーブ変換） | 90分 | ○ マスの外に置ける |
| **6** | **入力層の作り直し**（`input.js`／ドラッグ移動・リング回転） | 120分 | ○ **ここで「直感的に操作できる」が成立** |
| — | **2回目の実プレイ。操作が確定する** | | |
| **7** | **戦闘HUDをスマホ前提に**（トレイ・常時表示を削る） | 90分 | ○ |
| **8** | **段階的チュートリアル**（操作が確定してから） | 120分 | ○ |
| **9** | バランスの測り直し（測定器の凍結を解除） | 90分 | ○ |

**合計 約9時間。** 区切りは3段目（2.5時間）と6段目（6時間）です。

### 肥大化を防ぐ決まりごと

1. **各段のあと必ずコミットし、遊べる状態を保つ**
2. **測定器（`tools/sim.html`）は9段目まで凍結。** コアが動くたびに測り直すと、それだけで時間が溶ける
3. **3段目と6段目で必ず実プレイしていただく。** 合わなければその時点で方向を変える
4. **新しい武器・カード・ステージは追加しない**（C分類のまま）
