測定条件：375×812（iPhone相当）、`http://localhost:5173/`、コンソールエラー0。

## 1. UI・チュートリアル

### 現状の何が問題か

- **intro が9段落の一括表示。** 配置・射界・集弾率・カード・ヒートマップまで、遊ぶ前に全部説明している（`main.js:77-95`）
- **常時表示が多い。** HUD（ウェーブ／フェーズ／ステージ／コイン／DPS／ライフバー／ウェーブバー）＋ユニットトレイ＋制御ボタン4つ＋タブ6つが、初回から全部見えている
- **次に何を押すかの誘導が無い。** 「戦闘開始」は武器を置く前でも押せる（押すとトースト警告が出るだけ）
- **パネルが画面の45%を占める。** 盤面が55%しかない

### どこを変えるか

| ファイル | 変更内容 |
|---|---|
| `src/main.js` | `intro()` を削除し、段階的チュートリアルに置き換え |
| `src/tutorial.js`（新規・約120行） | 手順の定義と「次の1歩」の判定 |
| `src/ui.js` | チュートリアル中はタブとHUDの一部を隠す |
| `src/render.js` | 置くべき場所・押すべきボタンのハイライト描画 |
| `style.css` | ハイライトのアニメーション |

### 最小限でどこまで

**5ステップだけの初回導線**（`perm.tutorial` で進行を保存）。

1. 「ガトリングをここに置く」→ 盤面の1マスだけを光らせる。他はタップ不可
2. 「なぞって敵の来る方へ向ける」→ 経路の矢印を強調
3. 「戦闘開始」→ そのボタンだけを光らせ、他は隠す
4. 敵を1体倒したら「コインが増えた」を1行だけ
5. ウェーブ突破後「このコインで強化する」→ スキルタブの1項目だけ光らせる

**この間、タブは全部隠す。** 終わったら通常UIに戻す。

### 既存への影響

- セーブに `perm.tutorial` が1つ増える（既存セーブは未完扱い→初回だけ走る）
- **戦闘ロジックには触らない**
- `seenIntro` は廃止

### 完了条件と検証

- 新規セーブで開くと、最初に見えるのは**1文＋光った1マスだけ**
- 5ステップを終えるまでタブが出ない
- 2回目以降の起動では出ない
- 375px幅のスクリーンショットで、1画面の説明文が3行以内

### 30〜60分の代替案

**チュートリアルは作らず、intro を9段落→3行に削る。**「①地面に武器を置く ②なぞって向ける ③戦闘開始」。ハイライト無し。**15分。**

## 2. 武器の配置システム（自由配置）

### 現状の何が問題か

- `placeUnit(weaponId, c, r)` がタイル座標で、`buildable(c,r)` が `grid[r][c] === '#'` を見る（`state.js:243` / `stages.js:237`）
- **同じマスに1基まで**（`state.js:243`）。21pxのマスを指で選ばせている
- **移動が無い。** 撤去ボタン→再設置の2手（`ui.js:112`）
- **ドラッグは向き変更に使われている**（`main.js:192`）。移動に使えるジェスチャが残っていない

### 自由配置に必要な変更（影響範囲）

**ユニットの `x, y` は既に連続値です**（`stage.center(c,r)` から作っている）。描画も戦闘も `x,y` で動いています。**タイル座標に依存しているのは7箇所だけ**です。

| 箇所 | 現状 | 変更 |
|---|---|---|
| `state.js:243` | 同マス判定 | 半径での重なり判定に |
| `state.js:297` | セーブ `{c, r}` | `{x, y}` に（旧セーブは中心へ変換） |
| `state.js:319` | 復元 | 同上 |
| `state.js:225` | 既定の向き | `x,y` から求める |
| `render.js:139` | 配置可能マスの網目 | 「置ける領域」の塗りに |
| `main.js:143` | 指の下のユニット探索 | 半径での当たり判定に |
| `tools/sim.html:283` | 自動配置 | タイル中心を候補にすれば**そのまま動く** |

**経路計算・流れ場・敵の移動には一切触りません**（もともと `x,y`）。

### 最小限でどこまで

1. **`buildable` を点で判定する**：`buildableAt(x,y)` ＝ その点が属するタイルが `#`。**これだけで自由配置になります**
2. **重なり判定**：ユニット間 24px 以上。マス1基の制限を外す
3. **ドラッグで移動**：長押し150msで「つかむ」→ドラッグで移動、離して確定。**短いドラッグは今までどおり向き変更**
4. 撤去は据え置き

### 既存への影響

- **旧セーブの配置が壊れる。** `{c,r}` を読んだら中心座標に変換して救う
- **測定器の自動配置は候補がタイル中心のままなので、数字の連続性が保てる**
- 「マスに置ける数」の概念が消え、重ね置き防止は半径判定に一本化

### 完了条件と検証

- 1つのタイルの中で、ユニットを少しずつずらして置ける
- 2基を24px以内に置こうとすると弾かれる
- 長押し→ドラッグで動かせる／短いドラッグで向きが変わる
- 旧セーブ（`v3`）を読んでも配置が消えない
- `tools/sim.html` が従来と同じ結果を出す

### 30〜60分の代替案

**自由配置は保留し、「移動」だけ入れる。** `moveUnit(u, c, r)` を足し、長押し→ドラッグで別マスへ。撤去2手が1手になる。**40分。**

## 3. 敵の衝突・密集

### 現状の何が問題か

`combat.js:481-482` が流れ場の向きへ素直に進むだけで、**敵同士の判定が1行もありません。** 全員が同じ最短経路を同じ速さでなぞるので、重なって1本の線になります。

### 変えるもの

`src/combat.js` の敵更新ループのみ（**1ファイル・約20行**）。

**`Grid`（近傍検索）が既にあります**（`combat.js:403` で毎フレーム構築済み）。これを使うので**追加コストはほぼゼロ**です。

### 最小限でどこまで

```
移動後に、半径が重なっている相手から押し返す
  ・相手は Grid.query(e.x, e.y, e.r*2) で取る（既にある）
  ・重なり量の半分ずつ、互いに逆向きへずらす
  ・進行方向と垂直な成分を強め、前後方向は弱める
    → 横に広がって詰まる。前に押し戻されて進めなくなるのを防ぐ
  ・押し返したあと通れないタイルに出たら戻す（壁抜け防止）
```

**完全停止を防ぐ仕掛け**：押し返しの上限を「1フレームの移動距離」までにする。これで**前進が押し返しに負けません**。

### 既存への影響

**ここが一番大きいです。**

- **敵が密集すると範囲攻撃の価値が上がり、単体攻撃の価値が下がる** → 既存のバランス実測（1周26分など）は**全部やり直しになります**
- 経路が詰まるぶん**ウェーブが長くなる**可能性 → 「待ち時間」の数字も変わる
- 敵900体の上限で押し返し計算が毎フレーム走る → **スマホでの処理落ちを要確認**

### 完了条件と検証

- **まず grunt 1種類だけで実装する**
- 200体を1本道に流して、**1体も止まらずコアに到達する**（`tools/sim.html` で到達数を数える）
- 敵が重ならず横に広がって進む（スクリーンショット）
- スマホ幅で600体を出して**30fpsを割らない**
- その後 swift / tank を戻す

### 30〜60分の代替案

**押し返しをやめ、「前が詰まったら減速」だけにする。** 進行方向の前方 r×2 以内に敵が居たら速度を0.35倍。重なりは消えませんが、**列ができて密集は生まれます。** **25分**、処理も軽い。

## 4. スナイパーの役割

### 現状の何が問題か

| | ガトリング | スナイパー |
|---|---|---|
| ダメージ | 3.2 | 34 |
| 連射 | 5.5/秒 | 0.78/秒 |
| **DPS** | **17.6** | **26.5** |
| 射程 | 195 | 430 |
| 射界 | 0.34（39°） | 0.16（18°） |
| **貫通** | 0 | **1** |
| 狙う相手 | 最も近い | **最も硬い** |

**数字ではスナイパーのほうが強い（DPS 1.5倍・射程2.2倍）のに下位互換に感じる**理由は3つです。

1. **貫通1は「見えない」。** 1体目を貫いて2体目に当たるだけで、**貫通したという演出が無い**（`combat.js:652` はカウンタを減らすだけ）
2. **`target:'strongest'` が裏目。** 一番硬い敵＝たいてい後方のタンクを狙うので、**目の前の敵を素通りする**。1.28秒に1発しかないのに、その1発が遠くへ飛ぶ
3. **敵がすり抜けるので直線に並ばない**（3節）。貫通が活きる状況が盤面に存在しない

**「スナイパーが弱い」のではなく、貫通が機能する前提（密集）と、機能したことの表示が無い**のが原因です。

### 変えるもの

| ファイル | 変更 |
|---|---|
| `src/weapons.js` | sniper の `pierce` と `target` |
| `src/combat.js` | 貫通時の軌跡演出 |
| `src/render.js` | 貫通線の描画 |

### 最小限でどこまで

1. **`pierce: 1` → `3`**、`target: 'strongest'` → **`'dense'`**（`findTarget` に既にある「敵が多い方向」）
2. **貫通したら軌跡を残す**：`type:'beam'` を1つ足し、始点→終点の線を0.15秒描く。**当たった数だけ太くする**
3. ダメージ数字は既にあるので、貫通時は**複数体の上に連続して出る**（自然に「3体抜いた」が見える）

**3節（密集）が先です。** 密集しない盤面で貫通を強くしても実感できません。

### 既存への影響

- スナイパーのDPSが上がる（密集時は最大3倍）→ **長射程カテゴリのバランスが変わる**
- `dense` ターゲットは `findTarget` に既存なので**新規実装なし**
- カード `snp_rail`（貫通+99）の価値が相対的に下がる → 要再確認

### 完了条件と検証

- 1本道に敵を並べ、**1発で3体に同時にダメージ数字が出る**
- 貫通線が見える（スクリーンショット）
- 単体（ミサイル）／貫通（スナイパー）／範囲（火炎放射器）を1ステージずつ回し、**得意な場面が違うことが数字で出る**

### 30〜60分の代替案

**`target` を `'dense'` に変えるだけ。1行。** これだけで「目の前を素通りする」が消えます。**5分。**

## 5. 戦闘演出

### 現状の何が問題か

- **撃破時は `boom` 1種のみ**（`combat.js:166`、半径 r×1.5、0.22秒）。雑魚もボスも同じ形
- **コイン獲得の表示が無い。** `kill()` で加算するだけ（`combat.js:152`）。HUDの数字が静かに増える
- ダメージ数字はある（`combat.js:137`、上限70個）が、**会心・貫通・範囲の区別が無い**
- ボス撃破は画面揺れ16だけ（`combat.js:167`）

### 変えるもの

`src/combat.js`（fxの発行）と `src/render.js`（描画）のみ。**ゲームロジックには触りません。**

### 最小限でどこまで

| 演出 | 実装 | 効果 |
|---|---|---|
| **コインが飛ぶ** | 撃破位置からHUDのコイン表示へ、小さな◈が0.4秒で飛ぶ | 「倒す＝儲かる」が直結する |
| **貫通ビーム** | 4節と共通 | 貫通が見える |
| **範囲の爆発** | 既存 `boom` に輪を1本足す（半径が実際の爆風と一致） | どこまで届いたか分かる |
| **ボス撃破** | 0.6秒スローモーション＋白フラッシュ | 特別感 |
| **会心** | ダメージ数字を1.6倍の大きさ＋黄色 | 当たりが分かる |

**見えなくならないための決まりごと**

- 演出は**すべて敵より下のレイヤーに描く**（敵・ユニット・ボタンを隠さない）
- 同時に出るfxの上限を180→**120**に下げる
- **画面全体のフラッシュはボス撃破のみ**、不透明度0.25まで
- コインは**HUDの下**を通す

### 既存への影響

- **ロジックへの影響なし**（表示だけ）
- fx上限を下げるぶん、敵が多いときに演出が間引かれる（既にその設計）
- スマホの描画負荷は**増える**。600体時のfpsを要確認

### 完了条件と検証

- 撃破のたびにコインが飛ぶ（スクリーンショット）
- 600体・演出全部オンで**30fpsを割らない**（375px幅で計測）
- 演出中でもユニットと「戦闘開始」ボタンが読める

### 30〜60分の代替案

**コインが飛ぶ演出と会心の強調だけ。** 2つで **40分**。一番効くのはこの2つです。

## 6. 実装の順番

**3 → 4 → 5 → 2 → 1** を提案します。

| 順 | 項目 | 理由 | 概算 |
|---|---|---|---|
| **1番目** | **敵の衝突（3）** | **他の全部の前提。** 密集しない盤面では貫通も範囲攻撃も演出も価値が出ない。ここが変わるとバランスも全部変わるので、**先に済ませるほど手戻りが少ない** | 90分 |
| 2番目 | スナイパー（4） | 3の効果が一番はっきり出るのがここ。武器の役割差が生まれたか検証できる | 60分 |
| 3番目 | 演出（5） | 3と4で「何が起きているか」が増えたので、それを見せる | 90分 |
| 4番目 | 自由配置（2） | 操作の作り直し。3〜5と独立なので後でも手戻りが無い | 150分 |
| 5番目 | チュートリアル（1） | **一番最後。** 操作（2）が確定してからでないと、教える内容が変わって作り直しになる | 120分 |

**合計 約8.5時間。** 代替案だけなら **約2時間**（25+5+40+40+15分）。

### なぜチュートリアルが最後か

チュートリアルは「今の操作」を教えるものです。**2（自由配置）で操作が変わるなら、先に作ると必ず作り直しになります。**

### 手戻りの大きい順

| 項目 | 非可逆性 | 対策 |
|---|---|---|
| **敵の衝突** | **高**（バランス実測が全部無効になる） | grunt 1種で試作 → 数値を測ってから他の敵へ |
| **自由配置** | **中**（セーブ形式が変わる） | 旧 `{c,r}` を中心座標に変換して救う |
| チュートリアル | 低（表示だけ） | — |
| スナイパー | 低（数値2つ） | — |
| 演出 | 低（表示だけ） | — |

## 7. 進め方の提案

**まず「敵の衝突・grunt 1種だけ・減速方式（代替案25分）」から始めることを推奨します。**

押し返し方式（90分）と減速方式（25分）で、**密集が生まれるかどうかは同じように確かめられます。** 25分版で「密集が面白いか」を見てから、押し返しに進むか決められます。

その次に**スナイパーの `target` を1行変える（5分）**。この2つ、合計30分で「敵が密集して、貫通が刺さる」が体験できます。

**ご指示があるまでコードは変更しません。** 優先順位のご指定をお願いします。
