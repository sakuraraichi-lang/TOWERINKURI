## 1. 中核の規則（これが「全部に応用できる仕様」）

### 規則1 — 自動化は、自分の手でやったことだけを肩代わりする

> **一度でも自分の手で達成した範囲に限り、以後は機械が代わりにやる。**

これ1行で、いま在る／これから作る自動化が全部説明できます。

| 機能 | 「手でやった」の中身 | 肩代わりするもの |
|---|---|---|
| **まとめ買い**（実装済） | スキルを1つ手で買った | 同じスキルの買い足し |
| **倍速**（実装済） | — | 見ている時間 |
| **スキップ**（実装済） | そのステージを突破した | そのステージ1枚 |
| **一括突破**（新） | 連続するステージ群を**全部**突破した | その区間まるごと |
| **自動出撃**（新） | 1周を最後まで手でやり切った | 次の周の入口操作 |

**なぜこの規則か。**
「見たことのない内容を飛ばす」ことが起きません。飛ばせるのは、すでに自分が見て、
勝ち方を理解して、勝った場所だけです。だから**難易度も物語も壊れない**。
そして説明が1行で済むので、UIに長文を置かずにすみます（アイコン＋題名の方針と両立する）。

### 規則2 — 自動化は取り分を減らさない。ただし記録は更新しない

> **自動でやると、自分の最高記録と同じだけもらえる。最高記録は自分の手でしか伸びない。**

- ~~スキップの実装がすでにこの形（`Game.skipCoins` ＝ 前に手で突破したときの最高額）~~
  **【2026-09-22 ユーザー指示で変更】スキップは報酬を一切出さない**（チェックマークだけ・突破扱いにしない・前回到達章まで）。
  最高額を配っていたせいで30章を完全クリアされた、という報告がきっかけ。**いまのスキップはこの規則2に従っていない。**
  一括突破（下の 2-1）の取り分をこの規則2のままにするかは、決め直しが要る
- つまり**上を目指すのは常に手動、維持は自動**。自動化しても損しないので「損だから手でやる」が起きない
- 逆に「自動だけで永遠に伸びる」も起きない

### 規則3 — 自動化は、押した数だけ進む

> **放置で勝手に進む仕組みは入れない。** 1回の操作で、まとまった量が一気に進む。

インクリメンタルだが放置ゲームではない、という線引きです。
「オート進行」を**時間で回すもの**にすると、総時間の設計と衝突します（2026-09-21 以降は 3時間前後が基準）
（待ち時間がプレイ時間に化けるため）。**待たせずに一気に済ませる**。

## 2. 規則から出てくる4つの機能

### 2-1. 一括突破

**何か：** ホームで「ここまで一気に」を1回押すと、条件を満たした区間のステージを順に突破扱いにし、
結果をまとめて1枚の画面で見せる。

**解放条件（規則1）：** 区間の全ステージについて `clears >= 1`（手で突破済み）。
当時のスキップの条件（`SKIP_MIN_CLEARS: 3` かつ 転生1回以上、または完璧クリア。**いまは「踏破の記録」（`ky_skip`）＋前回到達章まで**）は
**1枚ずつの話**なので、区間版はそれより厳しくする必要はありません。
区間に含める条件がそのまま歯止めになります。

**取り分（規則2）：** 各ステージの `bestCoins` の合計。`bestPerfect` に従って完璧扱い。
→ 既存の `skipStage` を区間ぶん回すだけで済みます。

**所要時間（規則3）：** 演出込みで**数秒**。ステージごとに結果を送る演出は入れない。

**未決：** 区間の切り方。「今いる場所から、突破済みの最後まで」で足りるか、
プレイヤーに区間を選ばせるか。**選ばせる理由が今は見当たらないので、暫定で「突破済みの最後まで」1択。**

### 2-2. 自動出撃

**何か：** 転生した直後に「前回と同じ道を辿る」を1回押すと、
**一括突破で行ける所まで行って、そこで止まる。**

**解放条件（規則1）：** 1周（＝最終ステージ突破）を手でやり切ったことがある＝ `perm.prestiges >= 1`。
これは現行のスキップ条件と同じなので、新しい概念を増やしません。

**止まる場所：** 手で突破したことがある最後のステージ。その先は必ず手動。
**「前回の到達点までは一瞬、そこから先は自分の手」**が毎周の形になります。

**未決：** 編成とスキル振りを前回のまま引き継ぐか、毎回選ばせるか。
引き継ぐと周回が速いが、ビルドを変える動機が消える。**両方の実測が要る。**

### 2-3. 12ステージ化

**現状5枚。12枚にするなら、なぜ12枚かの根拠が要ります。**

いま言えること（実測）：

| | |
|---|---|
| 1周（5枚・測定器） | **21〜29分**（同じコードで3回測ってこの幅。振れ幅が大きい） |
| 1枚あたり | およそ 4〜6分 |
| 火力で1周を縮められる限界 | **1.9倍**（過去の実測。×12,000 と ×10⁴⁰ で1周の長さがほぼ同じ） |

ここから出る**暫定**の見立て：

- 12枚 = 1周およそ 50〜70分（手動・初回）
- ~~エンディングまで 5〜6時間 なら、**転生は4〜6回**が入る勘定~~
  **【2026-09-21】総時間は 3時間前後に変更。転生回数の勘定はここから引き直す（未着手）**
- ただし**2周目以降は一括突破で圧縮される**ので、周回の実時間は「新しく踏む枚数 × 4〜6分」に近づく

**これは仮説です。** 12という数字はまだ根拠を持っていません。
決めるために測るべきもの：

1. 「1枚あたり何分が飽きないか」——現状4〜6分。これが適正かはまだ聞いていません
2. 転生1回で伸びる到達枚数——**遺物の効きを測らないと出せない**
3. 上の2つが出れば、12枚が正しいか、8枚か16枚かが計算で出ます

**未決のまま置きます。数値を先に決めません。**

### 2-4. ラスボス → **取り下げ**

**2026-09-20 追記：ボスは実装しないことになりました。**

理由（実測）：ステージごとのボスは5ステージすべてで**撃破0**でした。
毎回漏れてライフを5持っていくだけで、コイン報酬は一度も支払われていません。
出す順番を「そのウェーブの最後」に変えても 7体中1体しか倒せませんでした。
**「倒せない1体に必ず税金を取られる」以上の役をしていなかった**ので、
ボスという仕組みごと外しました。

エンディングの締めをどう作るかは、改めて別の形で考えます（未決）。

## 3. この仕様が既存のどこに乗るか

実装するときに触る場所（調査済み・**まだ触っていません**）：

| | |
|---|---|
| `Game.canSkip / skipWhy / skipStage`（state.js） | 一括突破は、これを区間ぶん回す形で足せる |
| `Game.clearsOf / bestCoins / bestPerfect`（perm） | 規則2の「最高記録」はもう保存されている |

| `UI.showSkipResult`（ui.js） | 区間ぶんの結果を1枚にまとめる版が要る |

**新しいセーブ項目は要りません。** 規則1と規則2が、すでに保存してある
`clears` / `bestCoins` / `bestPerfect` / `prestiges` だけで表現できるためです。
