## 1-2. 30章の役割 【提案】

30章を**6つの幕**に分けます。幕ごとに「この期間に何を覚えるか」を1つだけ持たせます。

| 幕 | 章 | 役割（この幕で覚えること） | 転生の回数 |
|---|---|---|---|
| **I 導入** | 1–4 | 置く・向ける・絞る。カードを取る | 0 |
| **II 最初の壁** | 5–8 | 自分の戦力では足りない、と知る → **初回転生** | 1 |
| **III 恒久層** | 9–14 | 転生で残るものがある。ビルドを選ぶ | 2–3 |
| **IV 自動化** | 15–20 | 過去は一瞬で通れる。新しい章だけ考える | 4–5 |
| **V 特化** | 21–27 | 極端なビルドでないと通らない | 6–7 |
| **VI 決着** | 28–30 | 総決算。第30章に**ラスボス（§1-5 で再提案）** | 8 |

**各章の共通テンプレ**

| | |
|---|---|

| ウェーブ2 | その章の新要素（新しい敵）の**初見** |
| ウェーブ3 | 新要素が2つ重なる |
| ウェーブ4 | 密度の山。ここが一番落ちる |

## 1-3. 章ごとの新要素 【提案・粒度は幕まで】

30章ぶんの個別の敵構成は、いま細部まで作っても実装前に陳腐化します。
**幕ごとに「何を追加するか」だけを確定させ、章の割付は実装時に詰めます。**

| 幕 | 敵に足すもの | 地形に足すもの |
|---|---|---|
| I | grunt / swift | 一本道・折れ線 |
| II | tank | 分岐（2ルート） |
| III | **shield**（一定値以下のダメージを無効） | 合流点・島 |
| IV | **swarm**（小さく速く大量） | 3ルート・長距離 |
| V | **regen**（放置すると回復）／**splitter**（倒すと分裂） | 迂回路・広間 |
| VI | 上記の混成 | 第30章だけ固定マップ（生成しない） |

**なぜ敵に種類を足すのか**：数値を上げるだけだと、プレイヤーの対応が「もっと強い武器を置く」
の一手しかありません。**shield は単発高火力を、swarm は範囲を、regen は持続火力を、
splitter は処理順を要求します。**「どの武器が要るか」が章ごとに変わるのが、
ビルドを組み替える動機になります。

**未決**：各敵の具体的な数値。**敵の種類を足すこと自体が先で、数値は §5 の枠に後から嵌めます。**

## 1-5. ラスボス：取り下げたものと、何を変えて再提案するか 【提案】

### 取り下げた事実【確定】

本日、ステージごとのボスを**仕組みごと廃止**しました（コミット `867da78`）。根拠は実測です。

| 測ったこと | 値 |
|---|---|
| 5ステージでのボス出現 | 各1体（出てはいた） |
| **撃破** | **0体** |
| 支払われたコイン報酬 | **0** |
| 失ったライフ | 毎回5（漏れるため） |
| 出す順を「ウェーブの最後」に変えたあと | 7体中**1体**しか倒せず |

**壊れていた理由**：ボスHPが雑魚の26倍あり、しかも**最終ウェーブの最初の1体**として、
盤面に他の敵が1体もいない状態で湧いていました。首を振っている砲身の前を素通りするだけです。
つまり**「倒せない1体に必ず税金を取られる」**以上の役をしていませんでした。

設計書の「ラスボス」も、このとき一緒に取り下げています。

### それでも再提案する理由

ご指示に「最終章にラスボスを配置」「撃破によってエンディングとスタッフロール」とあり、
**一本のゲームとして締めが要る**のは同意です。
ただし**廃止したものをそのまま戻すと、同じ理由で同じように壊れます。**
壊れた原因は「HPが26倍」ではなく、**構造**だったからです。

### 何を変えるのか【提案】

| | 廃止したボス | **再提案するラスボス** |
|---|---|---|
| 出方 | ウェーブの中に混ざって湧く | **第30章の第5ウェーブが丸ごとラスボス戦**。雑魚と混ざらない |
| 通過 | **漏れれば通り抜けられる**（倒さなくても章は突破） | **倒すまで終わらない。**漏れという概念を持たない |
| 移動 | コアへ歩く | **歩かない。**その場に留まり、こちらのコアを攻撃してくる |
| 勝敗 | 倒せなくても進める | **削り切ればエンディング、ライフが尽きれば敗北** |
| 段階 | 無い | **3段階。**段階の切れ目に**ビルドフェーズが挟まる**（置き直せる） |
| HPの決め方 | 雑魚 ×26（根拠なし） | **「用意した戦力で何分かかるか」から逆算**（下記） |

**要点は「歩かせない」ことです。**
廃止したボスが壊れたのは、**通り抜けるという逃げ道があった**ためです。
その場に留まって殴り合う形にすれば、**倒せるまで何度でも挑む**という、
ボス戦として当たり前の形になります。これは廃止したものとは別の仕組みです。

### HPの決め方【提案】

**雑魚から外挿しません。**「何分の戦いにしたいか」から逆算します。

```
ラスボスHP = 第30章に到達したプレイヤーの想定DPS × 目標戦闘時間
```

- 目標戦闘時間の暫定：**3分**（3段階 × 1分）
- 第30章の想定戦力 N = 1.13×10¹⁴（§1-4 の表）
- **想定DPSは未計測。** フェーズ6で第30章が遊べる状態になってから測り、そこから決めます

**【未決】**：想定DPS。**これを測る前にHPを置きません。**
廃止したボスは「雑魚×26」という根拠のない外挿で置いて、結果0体しか倒せませんでした。
同じ失敗を繰り返さないため、**数値はフェーズ6まで空欄のままにします。**

### 3段階の中身【未決】

段階ごとに何が変わるか（出現口が増える／弱点が移る／一部の武器が無効になる、等）は
まだ決めていません。**幕Vまでに追加する敵4種（shield / swarm / regen / splitter）が
出そろってから、その総復習になるように組みます。**

# 6. 30章を通じた成長曲線と経済

## 6-1. 敵の曲線 【提案】

**1ウェーブごと ×1.25、1章（5ウェーブ）ごと ×3.05。**

```
HP(w) = HP0 × 1.25^(w-1)          w = 通算ウェーブ番号 1..150
HP0 = 20
第1章末(w=5)      49
第5章末(w=25)     4,400
第10章末(w=50)    1.4e6
第20章末(w=100)   1.3e11
第30章末(w=150)   1.1e14
```

**なぜ ×1.25 / ウェーブなのか**
- 5ウェーブで ×3.05。**1章を通して「敵が3倍硬くなる」**のは、章の中で成長が要ると感じる幅
- 30章で ×1.1×10¹⁴。**インクリメンタルとして十分な桁**（レビューの「傾斜急でいい」に沿う）
- 現行は 1章 ×5.01（`enemyHpGrowth 1.30`^5 × `stageHpMul 1.35`）。**30章では 5^29 = 1×10²⁰ で急すぎます**
- **`enemyHpGrowth` を 1.25、`stageHpMul` を 1.0（撤廃）にすると、ちょうど ×3.05/章になります**

**敵の数【提案】**
HPと同率で増やしません。**数は章ごとに ×1.15 程度**にとどめ、
200体前後で頭打ちにします。理由：数は処理落ちと画面の見やすさに直結するためです。
**「大群」は数値ではなく、swarm という敵の種類で作ります**（§1-3）。

**未決**：敵の速度・DPS の曲線。HPに引きずられて上げると、漏れた瞬間に即死になります。
**速度は章を通してほぼ据え置き、DPSは HP の 1/3 の傾き**を暫定案とします。

## 6-2. プレイヤーの曲線 【提案】

**1周（転生サイクル）の中での伸びと、周をまたぐ伸びを分けます。**

### 周の中（ツリー＋カード）

### 周をまたぐ（恒久層）

**規則【提案・訂正済み】**

> **転生後の恒久倍率 F は、「前回到達した章の必要戦力 N × 5」に追随する。**
>
> ```
> F(P) = N(前回到達章) × 5
> ```

**倍率が 10 ではなく 5 なのは、転生回数から逆算した結果です（2026-09-20 改定）。**
「どの周も、周で積む必要が ×3 以上」という基準を満たすには、
M=10 だと**毎周4章以上**進まねばならず、30章を最大7周＝**転生6回**でしか割れません。
ユーザーの回答は**転生8回**なので、M を 5 に下げて**毎周3章**を成立させました。
M は「既踏の最終章がどれだけ overkill になるか」なので、5 でも十分に trivial です。

**この規則は一度書き間違えました。** 最初「N ÷ 30」と書いていたのですが、

## 6-5. ウェーブ長の逆算 【未決・最優先】

§1-1 の前提「1ウェーブ 15〜20秒」を成立させる必要があります。

現行は湧きスケジュールでウェーブ長が決まり、通算W16で**湧きだけで77秒**でした。

**決め方**：ウェーブ長を 15〜20秒に固定し、そこから waveCount を毎章決めます

# 8. マップとステージ構成

## 8-1. 方式 【提案】

**完全ランダムにしません。「型 ＋ 乱数 ＋ 検証」の3層にします。**

| 層 | 中身 | 決まり方 |
|---|---|---|
| **型（固定）** | 通路の骨格。一本道／分岐／螺旋／島／三叉／広間 の6種 | **章ごとに固定** |
| **乱数** | 骨格の折れ点・障害物の位置・出現口の数 | **ステージ番号を種にする**（毎回同じ） |
| **検証** | 経路長・地面の数・十字砲火が組める地面の数 | **既存の `tools/genmaps.py` の検査をそのまま使う** |

**種を固定する理由**：毎回違うと「前回の配置」を復元できず、自動設置（§5）が作れません。
**ステージ番号から決まる**なら、何周目でも同じマップです。

## 8-2. 章ごとの変化 【提案】

| 幕 | 型 | 変化のさせ方 |
|---|---|---|
| I (1–4) | 一本道・折れ線 | 長さだけ変える |
| II (5–8) | 分岐（2ルート） | 分岐の位置 |
| III (9–14) | 螺旋・島 | 島の大きさ |
| IV (15–20) | 三叉・長距離 | ルート数 |
| V (21–27) | 広間・迂回路 | 開けた面の割合 |
| VI (28–30) | 混成 | **第30章だけ固定マップ**（生成しない） |

## 8-3. 武器の価値を壊さないための制約 【提案】

生成が武器の価値を壊す例と、それを防ぐ検査：

| 壊れ方 | 検査 |
|---|---|
| 一直線だけ → スナイパー一強、扇の広い武器が無価値 | **十字砲火が組める地面 ≧ 40**（既存の検査） |
| 通路が広すぎ → 扇でカバーしきれず設置数だけが効く | **平均通路幅 ≦ 4タイル** |
| 通路が短すぎ → 何を置いても間に合わない | **経路長 ≧ 20タイル**（既存） |
| 地面が少なすぎ → 置き場所の判断が消える | **地面 ≧ 90**（既存） |
| 出現口が1つだけ → 支援・指定攻撃が無価値 | **章が進むほど出現口を増やす**（幕IV以降は3以上） |

**既存の `genmaps.py` は上の3つを既に検査しています。** 追加するのは通路幅と出現口数だけです。

**未決**：第30章のマップ。生成せず手で作ります。
ラスボスは歩かないので（§1-5）、**「ボスの周りをどう囲めるか」だけを決める盤面**になります。形は未決。
