# 0. 全体像（1枚で）

```
                 ┌─────────────── 1周（転生サイクル） ───────────────┐
  起動 → 第1章 … 第N章（壁） → 転生 → 恒久成長 → 既踏章を一瞬で → 第N+k章（新しい壁）
                                  ↑                                    │
                                  └──────── 8回くりかえす ─────────────┘
                                                                       ↓
                                                       第30章 ラスボス → エンディング
```

**中心にある1本の規則【提案】**

> **「章」がラン（出撃）の単位。5ステージ＝1回の出撃の5区画。**
> **転生は「章を丸ごと過去にする」イベント。恒久層は、過去にした章の敵HPを基準に追いつく。**

この2行から、時間・解放順・自動化・経済のほとんどが導けます。以下で展開します。

# 1. ゲーム全体の進行設計（30章 × 5ステージ）

## 1-1. なぜ「章＝1出撃」なのか 【提案】

**150ステージを今の構造のまま作ると、確実に時間が破綻します。**

現行実測：1ステージ 4〜6分（5ウェーブ、各ウェーブの前後に準備フェーズ）。
150 × 5分 = **750分 = 12.5時間**。目標の 5〜6時間の倍以上です。
しかもこれは初回攻略ぶんだけで、転生後の再攻略を含みません。

ステージを短くするだけでは解けません。準備フェーズの出入りが1ステージにつき5回あり、
**「遊んでいる時間」より「画面を切り替えている時間」のほうが増える**からです。

そこで構造を変えます。

| | 現行 | 【提案】 |
|---|---|---|
| 出撃の単位 | 1ステージ | **1章（5ステージ）** |
| 準備フェーズ | 各ウェーブの間 | **各ステージの間だけ**（章の中で4回） |
| 1ステージ | 5ウェーブ | **3ウェーブ** |
| ライフ | ステージごとに全回復 | **章を通して持ち越し**（区画をまたいで減り続ける） |
| カードの3択 | ウェーブ突破ごと | **ステージ突破ごと**（章あたり4回） |
| 失敗 | そのステージをやり直し | **章の頭からやり直し** |

**得られるもの**

- 1章 = 15ウェーブ。ウェーブ1本 15〜20秒として **4〜5分**
- ライフが章を通して減るので、**「1ステージ目の損が5ステージ目に効く」**という緊張が生まれる
- カードのドラフトが章の中で4回 → **ビルドが1章の中で組み上がる**。ローグライトの形になる
- 「章」がプレイヤーにとっての一区切りとして意味を持つ（今は「ステージ」と「章」が二重になる）

**成立条件**：1ウェーブが 15〜20秒で終わること。
現行は湧きスケジュールでウェーブ長が決まっており、通算W16で湧きだけで77秒かかっていました。
**`spawnIntervalBase / Decay / Min` と `waveCount` を、ウェーブ長から逆算し直す必要があります**（§6-5）。

**未決**：章の途中で撤退したときの扱い。全損か、踏破した区画までは残すか。
→ 暫定は**全損**（章がランの単位なので）。ただし初回の数章は救済を入れる（§4）。

## 1-2. 30章の役割 【提案】

30章を**6つの幕**に分けます。幕ごとに「この期間に何を覚えるか」を1つだけ持たせます。

| 幕 | 章 | 役割（この幕で覚えること） | 転生の回数 |
|---|---|---|---|
| **I 導入** | 1–4 | 置く・向ける・絞る。カードを取る | 0 |
| **II 最初の壁** | 5–8 | 自分の戦力では足りない、と知る → **初回転生** | 1 |
| **III 恒久層** | 9–14 | 転生で残るものがある。ビルドを選ぶ | 2–3 |
| **IV 自動化** | 15–20 | 過去は一瞬で通れる。新しい章だけ考える | 4–5 |
| **V 特化** | 21–27 | 極端なビルドでないと通らない | 6–7 |
| **VI 決着** | 28–30 | 総決算。第30章にラスボス | 8 |

**各章の共通テンプレ**

| | |
|---|---|
| 区画1 | 前章の延長。ここで負けるなら準備不足 |
| 区画2 | その章の新要素（新しい敵・地形）の**初見** |
| 区画3 | 新要素が2つ重なる |
| 区画4 | 密度の山。ここが一番落ちる |
| 区画5 | 締め。抜けると章の報酬 |

**未決**：章ごとの固有名と物語。いまは番号で設計し、名前は後で乗せます。

## 1-3. 章ごとの新要素 【提案・粒度は幕まで】

150ステージぶんの個別設計は、いま作っても実装前に陳腐化します。
**幕ごとに「何を追加するか」だけを確定させ、章の割付は実装時に詰めます。**

| 幕 | 敵に足すもの | 地形に足すもの |
|---|---|---|
| I | grunt / swift | 一本道・折れ線 |
| II | tank | 分岐（2ルート） |
| III | **shield**（一定値以下のダメージを無効） | 合流点・島 |
| IV | **swarm**（小さく速く大量） | 3ルート・長距離 |
| V | **regen**（放置すると回復）／**splitter**（倒すと分裂） | 迂回路・広間 |
| VI | 上記の混成 | ラスボス専用の固定マップ |

**なぜ敵に種類を足すのか**：数値を上げるだけだと、プレイヤーの対応が「もっと強い武器を置く」
の一手しかありません。**shield は単発高火力を、swarm は範囲を、regen は持続火力を、
splitter は処理順を要求します。**「どの武器が要るか」が章ごとに変わるのが、
ビルドを組み替える動機になります。

**未決**：各敵の具体的な数値。**敵の種類を足すこと自体が先で、数値は §5 の枠に後から嵌めます。**

# 2. ゲーム開始から初回転生まで（詳細設計）

**この区間が一番大事です。** ここで「数字が増えるのが気持ちいい」と「自分の判断が効いている」の
両方が伝わらないと、あとの29章は全部無駄になります。

## 2-1. 初期状態 【提案】

| | |
|---|---|
| 武器 | **ガトリング 1種のみ**（現行はガトリング＋スナイパーの2種） |
| 設置枠 | 3基 |
| スキルツリー | **見えない**（第1章クリアまでタブごと非表示） |
| カード | **0枚所持**（現行は7枚持って始まる） |
| パック | **0個・タブ非表示** |
| 転生 | 存在を知らない |

**現行から変えるところ：初期所持カード7枚とスナイパーを外します。**
理由：最初の画面に「ガトリング／スナイパー／カード7枚／パック1個／スキルツリー27ノード」が
同時にあると、**何を見ればいいか分かりません。** 1章で1つずつ出します。

## 2-2. 第1章：置く・向ける（所要 4〜6分）

| 区画 | そこで初めて起きること | プレイヤーが学ぶこと |
|---|---|---|
| 1 | 武器を1基置く。敵が来る。倒す | **置けば倒せる** |
| 2 | 敵が2基目の射界の外を通る | **向きが要る** |
| 3 | **射界の調節バーが出る** | **絞ると当たる／広げると届く** |
| 4 | 敵が増えて漏れる | **足りなくなる** |
| 5 | 区画4で漏れたぶんライフが減ったまま戦う | **損は持ち越す** |

**章クリア報酬：スキルツリー解放 ＋ コイン**

ここで**初めて数字を買います。** ツリーは最初 **3ノードだけ**見えます
（火力／射程／設置枠）。27ノードを一度に見せません。

## 2-3. 第2章：伸ばす（所要 4〜6分）

- **カードの3択が初登場**（区画1突破後）。最初の3択は**全部ガトリング用**にして、
  「カードは武器の挙動を変えるもの」と分からせます
- ツリーのノードが 3 → 8 に増える
- **章クリア報酬：スナイパー解放**

**ここが「初めて強化の選択に迷う」地点【提案】**
第2章の終わりに、**コインが「火力3段」か「設置枠1段」のどちらか一方しか買えない額**になるよう
調整します。これが最初の意思決定です。

## 2-4. 第3章：選ぶ（所要 5〜7分）

- **編成タブ解放**（武器2種から選ぶ。枠は2）
- **基本パックが初登場**（章クリア報酬で1個）。**ここが最初のパックです**
- ツリー全ノード解放（27）

## 2-5. 第4章：組む（所要 5〜7分）

- **シナジーの存在を知らせる**（ガトリング×スナイパーの1組だけ提示）
- 敵に tank が混ざる → **単発火力が要る**と分かる

## 2-6. 第5–7章：壁（所要 15〜25分）

**ここで意図的に止めます。**

- 第5章：ぎりぎり抜ける
- 第6章：2〜3回落ちて抜ける
- **第7章：抜けられない。** ツリーを上限まで買っても届かない

**「上限まで買っても届かない」を明示する【提案】**
第7章で詰まったとき、ホームに **「戦力が足りません」** と、
**転生の入口**を出します。それまで転生タブは存在しません。

> 転生すると、コインとスキルツリーとステージ進行が消えます。
> **かわりに、消えないものが手に入ります。**

## 2-7. 初回転生（所要 2〜3分）

**報酬【提案】**

| | |
|---|---|
| **遺物パック ×3** | 転生でしか出ない。**これが「消えない層」の初対面** |
| **倍速 ×2 解放** | 再攻略が目に見えて速くなる |
| **スキップ解放（第1–3章）** | 手で3回以上抜けた章を飛ばせる |

**演出【提案】**
転生の瞬間に、**これまで倒した敵の総数と稼いだコインの総額**を出します。
「消える」ことを損に見せず、**「ここまでが1周目だった」**と伝えるためです。

## 2-8. 転生の前後で、何が変わるか 【提案】

| | 転生前（1周目） | 転生直後（2周目） |
|---|---|---|
| 第1章 | 4〜6分かけて手で攻略 | **スキップで数秒** |
| 第2–3章 | 4〜7分ずつ | **スキップで数秒** |
| 第4–6章 | 5〜7分ずつ | **手だが、2〜3分**（遺物で楽になっている） |
| 第7章 | **抜けられなかった** | **抜ける** |
| 到達 | 第6章まで | **第10章前後** |

**プレイヤーが実感すべきこと：「同じ場所が、こんなに楽になった」**
これが伝わらないと転生は苦役になります。だから**スキップを初回転生で必ず解放します。**

## 2-9. 初回転生までの所要時間 【仮説】

| | |
|---|---|
| 第1–4章 | 18〜26分 |
| 第5–7章（壁・リトライ込み） | 15〜25分 |
| ツリーとパックを見る時間 | 5〜10分 |
| **合計** | **38〜61分** |

**仮説である理由**：1ウェーブ15〜20秒が成立するかを測っていません。
**検証方法**：§10 のフェーズ1で、第1章だけ作って実測します。

# 3. 初回転生からエンディングまで

## 3-1. 転生サイクルの設計 【提案】

**8回の転生で30章。1周あたり平均 3.75章の前進。**

| 周 | 転生回数 | 到達章 | 新規に踏む章 | 実時間の見積 |
|---|---|---|---|---|
| 1 | 0 | 6 | 6 | 40〜60分 |
| 2 | 1 | 10 | 4 | 25〜35分 |
| 3 | 2 | 14 | 4 | 25〜35分 |
| 4 | 3 | 18 | 4 | 22〜30分 |
| 5 | 4 | 21 | 3 | 18〜25分 |
| 6 | 5 | 24 | 3 | 18〜25分 |
| 7 | 6 | 27 | 3 | 18〜25分 |
| 8 | 7 | 29 | 2 | 15〜20分 |
| 9 | 8 | **30（ラスボス）** | 1 | 15〜25分 |
| | | | **合計 30章** | **196〜280分（3.3〜4.7時間）** |

余白（迷う時間・ツリーを眺める時間・失敗の上振れ）を +30〜60分見て、
**5〜6時間**に収まる計算です。

**成立条件（ここが全部）**
> **既踏の章の再攻略が、合計で1周あたり3分以内に収まること。**

1周目に6章、9周目には29章を再攻略することになります。
29章を手で通したら、それだけで2時間です。**自動化が成立しなければこの設計は破綻します。**
→ §5 で、再攻略時間の上限を設計制約として置きます。

## 3-2. 転生で変わるもの（倍率だけにしない）【提案】

転生報酬を**4つの層**に分けます。ダメージ倍率は4つのうち1つだけです。

| 層 | 中身 | なぜ必要か |
|---|---|---|
| **① 数値** | 遺物（ダメージ・コイン・レート） | インクリメンタルの背骨 |
| **② 手数** | 初期投資（ツリーの初期レベル）・初動資金 | **登り直す時間を消す** |
| **③ 選択肢** | パックの解放・武器の解放・編成枠 | **ビルドが変わる** |
| **④ 速度** | 倍速・スキップ・一括突破・自動出撃 | **過去が過去になる** |

**「転生したのに何も変わらない」を防ぐ規則【提案】**

> **毎回の転生で、①〜④のうち最低2つが動く。**
> ①だけの転生を作らない。

## 3-3. 再攻略が加速する仕組み 【提案】

3段構えにします。

|---|---|---|
| **手で速く** | 恒久成長で、同じ章が2〜3分 → 1分に | 転生1回〜 |

**【提案】重複でランクが上がる**

完全指定にしない理由：毎回同じ3択になり、ローグライトでなくなるためです。

# 6. 30章を通じた成長曲線と経済

## 6-1. 敵の曲線 【提案】

**1ステージごと ×1.25、1章ごと ×3.05。**

```
HP(s) = HP0 × 1.25^(s-1)          s = 通算ステージ番号 1..150
HP0 = 20
第1章末(s=5)      49
第5章末(s=25)     4,400
第10章末(s=50)    1.4e6
第20章末(s=100)   1.3e11
第30章末(s=150)   1.2e16
```

**なぜ ×1.25 / ステージなのか**
- 5ステージで ×3.05。**1章を通して「敵が3倍硬くなる」**のは、章の中で成長が要ると感じる幅
- 30章で ×1.2×10¹⁶。**インクリメンタルとして十分な桁**（レビューの「傾斜急でいい」に沿う）
- 現行は 1ステージ ×5.01 で、**30章に引き伸ばすと 5^30 = 9×10²⁰ となり急すぎます**

**敵の数【提案】**
HPと同率で増やしません。**数は章ごとに ×1.15 程度**にとどめ、
200体前後で頭打ちにします。理由：数は処理落ちと画面の見やすさに直結するためです。
**「大群」は数値ではなく、swarm という敵の種類で作ります**（§1-3）。

**未決**：敵の速度・DPS の曲線。HPに引きずられて上げると、漏れた瞬間に即死になります。
**速度は章を通してほぼ据え置き、DPSは HP の 1/3 の傾き**を暫定案とします。

## 6-2. プレイヤーの曲線 【提案】

**1周（転生サイクル）の中での伸びと、周をまたぐ伸びを分けます。**

### 周の中（ツリー＋カード）

```
章の中で必要な伸び   ×3.05（敵と同率）
  内訳（提案）
    ツリー（コイン）   ×2.2
    カード3択（4回）   ×1.4
```

**これを予算として固定します。** いまは3つの源が勝手に足し算され、
実測で ×2.26 の章と ×10.41 の章ができていました。**予算制にすれば、そこが揃います。**

### 周をまたぐ（恒久層）

**規則【提案・訂正済み】**

> **転生後の恒久倍率 F は、「前回到達した章の必要戦力 N × 10」に追随する。**
>
> ```
> F(P) = N(前回到達章) × 10
> ```

**この規則は一度書き間違えました。** 最初「N ÷ 30」と書いていたのですが、
§1-4 の表を作って検算したところ**閉じませんでした**（周1が5%不足、周9では ×3.7×10¹² 過剰）。
基準を「第1章末の敵HP」に正規化していなかったのと、
恒久層を到達点より**下**に置いていたのが誤りでした。訂正後の検算が下です。

### 検算：ツリー＋カードの予算で足りるか

**周の中で積める倍率は、その周で新しく踏む章の数だけ**とします
（既踏の章はスキップするので、そこでは積まない）。

| 周 | 新しく踏む章 | 恒久倍率 F | 周末に要る N | 周で積む必要 | ツリー+カードで積める | 余裕 | 既踏最終章の overkill |
|---|---|---|---|---|---|---|---|
| 1 | 1–6（6章） | 1.00 | 265 | x265 | x805 | **x3.04** | — |
| 2 | 7–10（4章） | 2.65e3 | 2.30e4 | x8.67 | x87 | **x9.98** | x10 |
| 3 | 11–14（4章） | 2.30e5 | 1.99e6 | x8.67 | x87 | **x9.98** | x10 |
| 4 | 15–18（4章） | 1.99e7 | 1.73e8 | x8.67 | x87 | **x9.98** | x10 |
| 5 | 19–21（3章） | 1.73e9 | 4.91e9 | x2.84 | x28 | **x9.98** | x10 |
| 6 | 22–24（3章） | 4.91e10 | 1.40e11 | x2.84 | x28 | **x9.98** | x10 |
| 7 | 25–27（3章） | 1.40e12 | 3.97e12 | x2.84 | x28 | **x9.98** | x10 |
| 8 | 28–29（2章） | 3.97e13 | 3.69e13 | x0.93 | x9.30 | **x9.99** | x10 |
| 9 | 30–30（1章） | 3.69e14 | 1.13e14 | x0.31 | x3.05 | **x9.99** | x10 |

**読み取れること**

- **どの周も余裕 ×10 でそろいます。** これが「予算制」の効き目です
- **既踏の最終章は常に ×10 の overkill。** だから自動で飛ばせます
- **周8・9だけ「周で積む必要」が1を切っています**（×0.93 / ×0.31）。
  新しく踏む章が2章・1章と少ないため、恒久層だけで足りてしまう。
  → **到達章の割付（6/10/14/18/21/24/27/29/30）を組み直す必要があります。**
  基準は「**どの周も、周で積む必要が ×3 以上**」（＝最低でも1章ぶんは自力で登る）。**未決**

**成立条件**：遺物の獲得ペースが F に追随できること。
遺物は加算・累乗が混在しているので、**F に届くよう排出量と効果量を逆算する必要があります**。
これは**未決**です。§12 のフェーズ3で詰めます。

## 6-4. コインが余る問題の再定義 【提案】

**「余ること」自体は問題にしません。** インクリメンタルは余ってよいゲームです。
問題は**「余っているのに使い道がない」**ことです。実測で残高が次の1段の 118〜162,100倍でした。

**原因の内訳（実測済み）**

| 原因 | 状態 |
|---|---|
| 集金効率が ×1.11/段の累乗・上限なし（Lv39で ×153倍） | **潰した**（加算へ） |
| **リトライすると稼げる**（二面作戦で試行5回・雑魚7,769体） | **未解決** |
| 費用の伸び（×1.3/段）と収入の伸び（×桁/章）の次数が違う | **未解決** |

**【提案】3つ同時にやる**

1. **章クリア報酬を固定額にし、撃破コインの比重を下げる**
   → リトライしても総収入がほとんど増えない
2. **「大きな買い物」を章ごとに1つ置く**
   余剰の出口。例：設置枠の永続+1、編成枠+1、パック1個。
   **値段はその章の想定総収入の 60〜80%** にして、**毎章「1つだけ選ぶ」**形にする
3. **通常強化は安いままにする**
   まとめ買いで気持ちよく伸ばす層として残す

**目標帯【提案】**

| 区間 | 残高 ÷ 次の1段 | 体験 |
|---|---|---|
| 第1–4章 | **1〜5倍** | 買うか迷う |
| 第5–15章 | **10〜100倍** | まとめ買いが気持ちいい |
| 第16章以降 | **1,000倍以上でよい** | 桁が動くのを眺める。ただし「大きな買い物」は常に手が届かない |

**つまり「常に不足」は目指しません。** 序盤だけ締め、中盤以降は緩め、
**代わりに「大きな買い物」だけが常に1つ先にある**形にします。

## 6-5. ウェーブ長の逆算 【未決・最優先】

§1-1 の前提「1ウェーブ 15〜20秒」を成立させる必要があります。

現行は湧きスケジュールでウェーブ長が決まり、通算W16で**湧きだけで77秒**でした。
**`waveCount`（湧く数）と `spawnInterval`（間隔）を、目標ウェーブ長から逆算し直します。**

```
目標：ウェーブ長 = 湧き終わる時間 + 最後の1体を倒す時間 ≦ 20秒
  湧き終わる時間 = waveCount × spawnInterval
  → waveCount 40体、interval 0.3秒 なら 12秒。残り8秒で掃討
```

**未決**：150ステージを通した waveCount の曲線。
**決め方**：ウェーブ長を 15〜20秒に固定し、そこから waveCount を毎章決めます
（数を増やしたければ interval を詰める）。

## 7-2. 換装を独立させる 【提案】

現行、換装は他のパックに `swapChance` 20〜40% でおまけとして混ざっています。
**開けたら突然「換装を選べ」と出てくるので、何が起きたか分かりません。**

→ **換装パック**として独立させ、**転生5回で解放**します。
「ツリーの方向を変える道具」という役割が、パックの名前だけで伝わります。

## 7-3. カードとビルドの関係 【提案】

**カードは倍率ではなく、挙動を変えるものを主役にします。**

現行84枚の内訳：mod 47 / weapon 12 / perm 13 / synergy 9 / generic 3。
mod 47枚のうち、**「ダメージ ×1.32」のような倍率だけのカードが過半**です。

**【提案】mod を3種に分類し、比率を決める**

| 分類 | 例 | 比率の目標 |
|---|---|---|
| **倍率** | ダメージ ×1.32 | **30%**（今より減らす） |
| **挙動** | 弾が貫通する／扇を広げると同時発射が増える | **50%** |
| **取引** | 精度を捨てて火力／レートを捨てて爆風 | **20%** |

「アイテムとシナジーはこのまま調整してから追加」とのことなので、
**枚数は増やさず、既存47枚の中身を上の比率に寄せます。**

# 8. マップとステージ構成

## 8-1. 方式 【提案】

**完全ランダムにしません。「型 ＋ 乱数 ＋ 検証」の3層にします。**

| 層 | 中身 | 決まり方 |
|---|---|---|
| **型（固定）** | 通路の骨格。一本道／分岐／螺旋／島／三叉／広間 の6種 | **章ごとに固定** |
| **乱数** | 骨格の折れ点・障害物の位置・出現口の数 | **ステージ番号を種にする**（毎回同じ） |
| **検証** | 経路長・地面の数・十字砲火が組める地面の数 | **既存の `tools/genmaps.py` の検査をそのまま使う** |

**種を固定する理由**：毎回違うと「前回の配置」を復元できず、自動設置（§5）が作れません。
**ステージ番号から決まる**なら、何周目でも同じマップです。

## 8-2. 章ごとの変化 【提案】

| 幕 | 型 | 変化のさせ方 |
|---|---|---|
| I (1–4) | 一本道・折れ線 | 長さだけ変える |
| II (5–8) | 分岐（2ルート） | 分岐の位置 |
| III (9–14) | 螺旋・島 | 島の大きさ |
| IV (15–20) | 三叉・長距離 | ルート数 |
| V (21–27) | 広間・迂回路 | 開けた面の割合 |
| VI (28–30) | 混成 | ラスボスは**固定マップ**（生成しない） |

## 8-3. 武器の価値を壊さないための制約 【提案】

生成が武器の価値を壊す例と、それを防ぐ検査：

| 壊れ方 | 検査 |
|---|---|
| 一直線だけ → スナイパー一強、扇の広い武器が無価値 | **十字砲火が組める地面 ≧ 40**（既存の検査） |
| 通路が広すぎ → 扇でカバーしきれず設置数だけが効く | **平均通路幅 ≦ 4タイル** |
| 通路が短すぎ → 何を置いても間に合わない | **経路長 ≧ 20タイル**（既存） |
| 地面が少なすぎ → 置き場所の判断が消える | **地面 ≧ 90**（既存） |
| 出現口が1つだけ → 支援・指定攻撃が無価値 | **章が進むほど出現口を増やす**（幕IV以降は3以上） |

**既存の `genmaps.py` は上の3つを既に検査しています。** 追加するのは通路幅と出現口数だけです。

**未決**：ラスボスのマップ。生成せず手で作りますが、形はまだ決めていません。

# 11. エンディングまでの想定プレイ時間

## 11-1. 内訳 【仮説】

| | 時間 |
|---|---|
| 初回攻略（30章を初めて踏む） | 30章 × 4〜5分 = **120〜150分** |
| 失敗とリトライ（章の2〜3割で1回落ちる） | **+30〜50分** |
| 再攻略（8周ぶんの合計） | **+10〜20分**（自動化前提） |
| ツリー・パック・編成を見る時間 | **+30〜45分** |
| 転生の手続き（9回） | **+10分** |
| ラスボス | **+10〜20分** |
| **合計** | **210〜295分（3.5〜4.9時間）** |

余白を含めて **5〜6時間**に収まります。

## 11-2. この見積もりが崩れる条件 【重要】

| 崩れ方 | どうなるか |
|---|---|
| 1ウェーブが20秒を超える | **1章5分が7分になり、合計が1.5倍**（7時間超） |
| 再攻略が1周3分を超える | 周9で29章 → **30分/周 × 8周 = 4時間の追加** |
| 章の失敗率が5割を超える | **+60分以上** |

**つまり、5〜6時間を守る鍵は「ウェーブ長」と「再攻略の自動化」の2点だけです。**
他の数値は多少ずれても吸収できます。

本編の完成条件に含めません。150章とラスボスとエンディングが成立してから着手します。
