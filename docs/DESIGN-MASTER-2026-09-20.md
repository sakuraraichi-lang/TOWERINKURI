## 1-5. ラスボス：取り下げたものと、何を変えて再提案するか 【提案】

### 取り下げた事実【確定】

本日、ステージごとのボスを**仕組みごと廃止**しました（コミット `867da78`）。根拠は実測です。

| 測ったこと | 値 |
|---|---|
| 5ステージでのボス出現 | 各1体（出てはいた） |
| **撃破** | **0体** |
| 支払われたコイン報酬 | **0** |
| 失ったライフ | 毎回5（漏れるため） |
| 出す順を「ウェーブの最後」に変えたあと | 7体中**1体**しか倒せず |

**壊れていた理由**：ボスHPが雑魚の26倍あり、しかも**最終ウェーブの最初の1体**として、
盤面に他の敵が1体もいない状態で湧いていました。首を振っている砲身の前を素通りするだけです。
つまり**「倒せない1体に必ず税金を取られる」**以上の役をしていませんでした。

設計書の「ラスボス」も、このとき一緒に取り下げています。

### それでも再提案する理由

ご指示に「最終章にラスボスを配置」「撃破によってエンディングとスタッフロール」とあり、
**一本のゲームとして締めが要る**のは同意です。
ただし**廃止したものをそのまま戻すと、同じ理由で同じように壊れます。**
壊れた原因は「HPが26倍」ではなく、**構造**だったからです。

### 何を変えるのか【提案】

| | 廃止したボス | **再提案するラスボス** |
|---|---|---|
| 出方 | ウェーブの中に混ざって湧く | **第30章の第5ウェーブが丸ごとラスボス戦**。雑魚と混ざらない |
| 通過 | **漏れれば通り抜けられる**（倒さなくても章は突破） | **倒すまで終わらない。**漏れという概念を持たない |
| 移動 | コアへ歩く | **歩かない。**その場に留まり、こちらのコアを攻撃してくる |
| 勝敗 | 倒せなくても進める | **削り切ればエンディング、ライフが尽きれば敗北** |
| 段階 | 無い | **3段階。**段階の切れ目に**ビルドフェーズが挟まる**（置き直せる） |
| HPの決め方 | 雑魚 ×26（根拠なし） | **「用意した戦力で何分かかるか」から逆算**（下記） |

**要点は「歩かせない」ことです。**
廃止したボスが壊れたのは、**通り抜けるという逃げ道があった**ためです。
その場に留まって殴り合う形にすれば、**倒せるまで何度でも挑む**という、
ボス戦として当たり前の形になります。これは廃止したものとは別の仕組みです。

### HPの決め方【提案】

**雑魚から外挿しません。**「何分の戦いにしたいか」から逆算します。

```
ラスボスHP = 第30章に到達したプレイヤーの想定DPS × 目標戦闘時間
```

- 目標戦闘時間の暫定：**3分**（3段階 × 1分）
- 第30章の想定戦力 N = 1.13×10¹⁴（§1-4 の表）
- **想定DPSは未計測。** フェーズ6で第30章が遊べる状態になってから測り、そこから決めます

**【未決】**：想定DPS。**これを測る前にHPを置きません。**
廃止したボスは「雑魚×26」という根拠のない外挿で置いて、結果0体しか倒せませんでした。
同じ失敗を繰り返さないため、**数値はフェーズ6まで空欄のままにします。**

### 3段階の中身【未決】

段階ごとに何が変わるか（出現口が増える／弱点が移る／一部の武器が無効になる、等）は
まだ決めていません。**幕Vまでに追加する敵4種（shield / swarm / regen / splitter）が
出そろってから、その総復習になるように組みます。**

### 穴②：**転生報酬が第9章から先、深さで増えない**

`Pack.prestigeReward` は `clamp(round(突破数^1.7) + …, 1, BAL.packPerPrestigeMax)`。
**`packPerPrestigeMax` が 25 なので、突破9章で上限に当たります。**

**塞ぎ方（案）**：落とす順を `['basic', 'arms', 'chem', 'syn']`（手前から）にする。

そこを足すといくつになるかは、**人が実際に遊んで計るしかありません。**

**【いまの位置 2026-09-22】** 上の実測（121〜150分）が、失敗のやり直しも
再攻略も**全部込み**の数字です（`progressAsync` は失敗したら同じ章を最大4回まで挑み直し、
鍵を取ったあとはスキップも使います）。ここに入っていないのは**人間の操作時間だけ**。

~~合計 172〜235分（2.9〜3.9時間）。目標の 5〜6時間に対して余っています。~~
**この見積は取り下げます**（実測に置き換えたため。§13 #11）。

**成立条件（ここが全部）**
> **既踏の章の再攻略が、合計で1周あたり3分以内に収まること。**

1周目に6章、9周目には29章を再攻略することになります。
29章を手で通したら、それだけで2時間です。**自動化が成立しなければこの設計は破綻します。**
→ §5 で、再攻略時間の上限を設計制約として置きます。

## 3-2. 転生で変わるもの（倍率だけにしない）【提案】

転生報酬を**4つの層**に分けます。ダメージ倍率は4つのうち1つだけです。

| 層 | 中身 | なぜ必要か |
|---|---|---|
| **① 数値** | 遺物（ダメージ・コイン・レート） | インクリメンタルの背骨 |
| **② 手数** | 初期投資（ツリーの初期レベル）・初動資金 | **登り直す時間を消す** |
| **③ 選択肢** | パックの解放・武器の解放・編成枠 | **ビルドが変わる** |
| **④ 速度** | 倍速・スキップ・一括突破・自動出撃 | **過去が過去になる** |

**「転生したのに何も変わらない」を防ぐ規則【提案】**

> **毎回の転生で、①〜④のうち最低2つが動く。**
> ①だけの転生を作らない。

## 3-3. 再攻略が加速する仕組み 【提案】

3段構えにします。

| 段 | 何が起きるか | 解放 |
|---|---|---|
| **手で速く** | 恒久成長で、同じ章が2〜3分 → 1分に | 転生1回〜 |
| **飛ばす** | 章スキップ。数秒 | 転生1回＋その章を3回突破 |
| **まとめて飛ばす** | 一括突破。既踏区間を1タップ | 転生3回 |
| **自動で出る** | 自動出撃。転生直後に前回到達点まで自動 | 転生5回 |

**敵の数【提案】**
HPと同率で増やしません。**数は章ごとに ×1.15 程度**にとどめ、
200体前後で頭打ちにします。理由：数は処理落ちと画面の見やすさに直結するためです。

現行、換装は他のパックに `swapChance` 20〜40% でおまけとして混ざっています。
**開けたら突然「換装を選べ」と出てくるので、何が起きたか分かりません。**

→ **換装パック**として独立させ、**転生5回で解放**します。
「ツリーの方向を変える道具」という役割が、パックの名前だけで伝わります。

## 7-3. カードとビルドの関係 【提案】

**カードは倍率ではなく、挙動を変えるものを主役にします。**

現行84枚の内訳：mod 47 / weapon 12 / perm 13 / synergy 9 / generic 3。
mod 47枚のうち、**「ダメージ ×1.32」のような倍率だけのカードが過半**です。

**【提案】mod を3種に分類し、比率を決める**

| 分類 | 例 | 比率の目標 |
|---|---|---|
| **倍率** | ダメージ ×1.32 | **30%**（今より減らす） |
| **挙動** | 弾が貫通する／扇を広げると同時発射が増える | **50%** |
| **取引** | 精度を捨てて火力／レートを捨てて爆風 | **20%** |

「アイテムとシナジーはこのまま調整してから追加」とのことなので、
**枚数は増やさず、既存47枚の中身を上の比率に寄せます。**

# 8. マップとステージ構成

## 8-1. 方式 【提案】

**完全ランダムにしません。「型 ＋ 乱数 ＋ 検証」の3層にします。**

| 層 | 中身 | 決まり方 |
|---|---|---|
| **型（固定）** | 通路の骨格。一本道／分岐／螺旋／島／三叉／広間 の6種 | **章ごとに固定** |

**並べると「line が重く fork が軽い」ように見えます。** ですが、**これは読めません。**

### なぜ読めないか ―― 型と章番号が完全に重なっている

`tools/gen30.py` は**幕ごとに型を固定**しているので、
**「line の章」＝「浅い章」、「fork の章」＝「その次の章」**になっています。
掃討秒の差が**形のせいなのか、章が進んでプレイヤーが強くなったせいなのか、分離できません。**

しかも第5〜8章（fork）は、私が `chapterMul` で 2.0〜3.8倍に厚くした区間です。
**厚くする前は 52/35/30/34/31 秒で、ここが谷でした。**
谷の原因は「武器が2〜3種しかなくコインが集中する」ことで説明がつくので、
**形は関係なかった可能性のほうが高い**と見ています。

### 交差（十字砲火が組める地面）は、そもそも差が付いていない

30章すべてで **155〜190** に収まっています。**いまの型の違いは、ここを動かしていません。**
「形で難易度を作る」なら、**まずこの指標が章ごとに散る必要があります。**

### 形の効果を測るには、こういう実験が要ります 【まだやっていません】

> **同じ章番号（＝同じ敵の強さ・同じ所持カード）で、マップだけ差し替えて比べる。**

測定器は `runStage(stageId, ...)` でステージを指定できるので、
**「第10章の敵で、第1章の形／第5章の形／第15章の形を走らせる」**ことができれば分離できます。
ただし**いまの `Stage.build` は章とマップが1対1**なので、
**マップだけ差し替える口が測定器にありません。** そこを作るのが先です。

**この実験をやらないまま「形で難易度を調節する」を設計に入れると、
効いていないものを効いていると思い込んだまま30章ぶん作ることになります。**
（`chapterMul` のような数値のノブは形と独立に効くことが実測できているので、
形が効かなくても難易度そのものは作れます。**形は「見た目の変化」と
「配置の判断が変わること」のために要る**、と切り分けておくのが安全です）
