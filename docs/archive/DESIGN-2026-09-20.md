# 0. 最初に — 実測で見つかった、設計上いちばん重い事実

## **転生しても、ほとんど楽になっていません。**［実測］

測定器で「1周 → 転生 → 2周目」を通しました。

| 転生する時点 | 1周目 | 2周目 | **速くなった倍率** | 試行回数 |
|---|---|---|---|---|
| ステージ2突破で転生 | 9.8分 | 9.9分 | **0.99倍** | 5 → 4 |
| ステージ5突破で転生 | 23.1分 | 20.9分 | **1.10倍** | 11 → 9 |

あなたが作りたいと書かれた
**「以前は苦戦した敵の群れを一掃できるようになる」が、今のゲームでは起きていません。**

### なぜ起きないか

転生で消えるものと残るものの、**桁が合っていません**。

| | 1周で積み上がるもの | 転生後に残るもの |
|---|---|---|
| スキル合計レベル | **492** | 0（全消し） |
| 中射程ダメージ倍率 | **×132.8** | **×1.35**（転生倍率のみ） |
| ステージ進行 | 5/5 突破 | 0/5（`perm.stages = {}` で戻す） |

**×132 を捨てて ×1.35 をもらう**構造なので、2周目は1周目とほぼ同じ道のりを、
ほぼ同じ時間かけて登り直すことになります。

> これは「数値が悪い」のではなく、**構造の問題**です。
> 恒久層（消えないもの）が、周回層（消えるもの）に対して小さすぎます。
> 数字を触っても直りません。**転生の設計そのものを変える必要があります。**

## もうひとつ — 「大量の敵」は、本編では起きていません［実測］

| | |
|---|---|
| 1ウェーブの敵数 | 通算W1で **33体**、通算W25で **249体**（`24 + 9×w`） |
| 上限 `waveCountMax` | 600（**本編では一度も到達しません**） |
| 既存5マップの通路に入る敵の上限 | **258〜437体** |

つまり **600体に上げても、既存マップには入りません。**
「大量の敵が押し寄せる」体験は、**敵数だけでなくマップの形とセット**でしか作れません。

# 1. ゲーム開始から初回転生までの体験案

## 設計の原則

**1回に1つしか新しいものを出しません。** 今は起動直後にカード3択・スキルツリー全部・
パック1個が同時にあり、何を見ればいいか分かりません。

## 案：初回転生まで ＝ 約25〜35分、4つの「気づき」［仮説］

| 時間 | 場面 | プレイヤーが覚えること | 新しく開くもの |
|---|---|---|---|
| **0〜2分** | st1 W1〜2 | 置く／向ける／眺める | ガトリング**1種・3基**だけ |
| **2〜5分** | st1 W3〜5 | **扇の外は撃たない**（初めて漏らす） | 射界バー／1回目の敗北 |
| **5〜8分** | st1 再挑戦 | **負けてもコインは残る** | **スキルツリー（資源・拠点の2本だけ）** |
| **8〜12分** | st1 突破 | 突破の報酬 | **スナイパー**＋**ウェーブ間のカード3択** |
| **12〜20分** | st2 | **武器には役割がある**（面で溶かす／線で貫く） | カテゴリ別スキル（持っている2カテゴリのみ） |
| **20〜28分** | st2 突破 | 硬い敵・多い敵で要求が違う | **パック1個**＋**パックタブ** |
| **28〜35分** | st3 で詰まる | **もう一周したほうが速い** | **転生が解禁される** |

### 今との差分

| | 今 | 案 |
|---|---|---|
| 開始時の武器 | ガトリング＋スナイパー（2種） | **ガトリングのみ** |
| カードの3択 | 最初のウェーブから出る | **st1 突破後** |
| スキルツリー | 最初から全ノードが並ぶ | **2本 → 突破ごとに増える** |
| パック | 最初から1個持っている | **st2 突破で初めて1個** |
| 転生 | st2 突破で解禁（`prestigeMinStages: 2`） | **st3 で詰まってから**（体験として） |

### 「最初の敗北」を設計に組み込む

今は st1 の初回でだいたい負けます［実測：1周目で試行11回］。これは**悪いことではなく、
「負けてもコインは残る」を教える最短の道**です。案では**1回目の敗北を導線に組み込み**、
敗北画面で「持ち帰ったコイン」を主役にします。

# 2. 序盤・中盤・終盤の成長設計

## 進行の軸を3本にする［仮説］

今は「ステージ5枚 × 5ウェーブ ＝ 25ウェーブ」で終わりです。
インクリメンタルとしての**長さが無い**ので、縦の軸を足します。

| 軸 | 何が変わるか | 長さ |
|---|---|---|
| **① ステージ（地形）** | 通路の形。どこに置けるか | 有限（5〜8枚） |
| **② 階層（難易度）** | 敵HPと敵数の倍率。**マップも広くなる** | 無限。**数値インフレの受け皿** |
| **③ 転生** | 恒久強化と、新しい成長手段 | 無限。**「圧倒」を作る層** |

> 参考画像1枚目の `NORMAL STAGE 9` と同じ考え方です。
> 地形はローテーションし、難易度は階層で上げます。

## 3段階の体験

| | 序盤（階層1） | 中盤（階層2〜4） | 終盤（階層5〜） |
|---|---|---|---|
| **敵の数** | 25〜150体 | 150〜600体 | 600〜2000体 |
| **戦場** | 標準（15×21） | 中（21×30） | **広大（30×42）＋カメラ** |
| **武器の数** | 1〜3種 | 4種を選ぶ（編成が意味を持つ） | 4種＋シナジー |
| **設置数** | 3〜8基 | 11〜19基 | **31基**［実測：スキル最大時］ |
| **やっていること** | 1基ずつ置いて向ける | 射線を重ねる／役割分担 | **陣地を設計する** |
| **壁の正体** | 扇の向き | 編成とカテゴリ選択 | 恒久層の厚み |

**戦場が成長に合わせて大きくなる**のは、あなたの案のとおり必要です。
**敵数を増やしても、マップが狭いと画面に出ないため**［実測：上限258〜437体］。

# 3. 数値インフレの関係

## いま動いている成長率［実測・コードから］

| | 式 | 1ウェーブあたり | 通算25ウェーブで |
|---|---|---|---|
| 敵HP | `19 × 1.30^w × 1.35^stage` | **×1.30** | ×705（＋ステージ ×3.3） |
| 敵数 | `24 + 9w`（上限600） | +9 | 33 → 249体 |
| 敵の足 | `112 × 1.012^w`（上限260） | ×1.012 | ×1.35 |
| 敵が落とすコイン | `2.4 × 1.19^w` | **×1.19** | ×70 |
| スキルの値段 | `cost0 × (1.28〜1.36)^lv` | — | レベルごと ×1.3前後 |
| プレイヤーDPS | スキル `1.13〜1.18^lv` ×カード ×転生 | — | **×133**［実測］ |

## いちばん大事な関係は、3つの比です

### 比1：**敵HP ×1.30/w に対して、コイン ×1.19/w**

コインのほうが遅いので、ウェーブが進むほど買えなくなります。
**これは正しい設計です。** 壁はここで生まれます。

### 比2：**スキルコスト ×1.30/lv に対して、コイン収入 ×1.19/w**

コストのほうが速いので、**1周で到達できるDPSに天井があります**。［実測：中射程 ×133］

### 比3（壊れている）：**1周の天井 ×133 に対して、恒久層 ×1.35**

**ここが 0 節の問題です。** 恒久層が天井の 1% しかないので、
何周しても同じところを登り直します。

## 提案する関係［仮説］

**恒久層の大きさを、「1周の天井」と同じオーダーに乗せます。**

| 層 | 役割 | 成長のさせ方（案） |
|---|---|---|
| **周回層**（消える） | 1周の中の壁を作る | 今のまま。コイン → スキル。天井 ×100〜200 |
| **恒久層**（消えない） | 次の周を短くする | **転生ごとに ×1.6〜2.0**、かつ**開始時スキルレベル**を持つ |
| **階層** | 長さを作る | 階層ごとに 敵HP ×4、敵数 ×1.6 |

**「開始時スキルレベル」が要点です。** 倍率だけ増やしても、
**登り直す時間は変わりません**（今がまさにそれ）。
恒久層が「スキルツリーの下のほうを買った状態で始める」を提供すれば、
**道のりそのものが短くなります。**

### 目標にする数字［仮説・測れる］

| | 今［実測］ | 目標 |
|---|---|---|
| 同じ深さを2周目で回る速さ | **0.99〜1.10倍** | **3.0倍** |
| 2周目に到達できる深さ | 同じ（5/5） | **階層を1つ上げて到達** |
| 1周の所要時間 | 19〜28分 | **［未決］** — 長いか短いかの判断が要ります |

**この3つは測定器で毎回測れます。** 数字を触るたびに確認できます。

## 敵数と敵の強さを分ける［仮説］

あなたのご指摘どおり、分けます。

| | 今 | 案 |
|---|---|---|
| 敵数 | ウェーブ番号で増える（`24+9w`） | **階層で増える**。階層内は緩やかに |
| 敵HP | ウェーブ番号とステージで増える | ウェーブ番号と**階層**で増える |

案の式（仮）：

```
敵数 = (20 + 5×w) × 1.6^(階層-1)      上限はマップの収容力で決める
敵HP = 19 × 1.28^w × 4^(階層-1) × 地形補正
```

- 階層1・W1 = **25体**（今の33体より少ない。序盤は少数でいい）
- 階層1・W25 = 145体
- 階層4・W25 = **594体**（このとき戦場は広大マップ）

**「敵を増やす局面」と「1体を強くする局面」の分け方**：

| 局面 | どちらを動かすか | 狙い |
|---|---|---|
| ウェーブが進む（周回内） | **HPを上げる**（×1.28/w） | 火力の壁。編成を考えさせる |
| 階層が上がる（周回間） | **数とHPを両方**（×1.6 / ×4） | 絵が変わる。戦場が広がる |
| ボスウェーブ | **1体を極端に強く**（×26）［今のまま］ | 指定攻撃・貫通の出番 |

# 5. 転生の設計

## 今の転生［実測・コードから］

| | |
|---|---|
| 条件 | 2ステージ突破 |
| 失うもの | コイン・スキル全部・**ステージ進行**（`perm.stages = {}`） |
| 残るもの | カード・パック・到達深度・転生回数 |
| もらうもの | 恒久 **×1.35**（火力とコイン）＋パック（`突破数^1.7`） |
| **効果**［実測］ | **2周目が 0.99〜1.10倍の速さ** ＝ ほぼ変わらない |

## 作り直し案［仮説］

### 変更点1：**ステージ進行を戻さない**

今は転生のたびに st1 からやり直します。これが「同じ道のりを登り直す」原因です。

- **突破したステージは突破したまま**にする
- 代わりに、**次の階層は st1 から**（階層が上がると地形の意味が変わるので、これは苦行になりません）

### 変更点2：**恒久ツリーを別枠で作る**

転生で「**遺物ポイント**」を得て、**転生では消えないツリー**に振ります。
今のスキルツリー（コインで買う・転生で消える）とは別枠です。

| 恒久ノードの例 | 効果 | なぜ「圧倒」につながるか |
|---|---|---|
| **初期投資** | 出撃開始時にスキルツリーが Lv+N の状態 | **登り直す時間が消える**。ここが本命 |
| 恒久火力 | 全カテゴリ ×1.15/Lv | 今の ×1.35 の置き換え |
| 恒久収入 | コイン ×1.20/Lv | 買うテンポが上がる |
| 常設基盤 | 設置数 +1 | 陣地が広がる |
| 開幕装填 | 出撃開始時にカード1枚 | ビルドの立ち上がりが速い |
| 深度記憶 | 到達済みのウェーブを**まとめて飛ばす**（スキップ） | **過去の難所を文字通り飛ばす** |

> **「深度記憶」が、あなたの言う「圧倒」に最も直接効きます。**
> 「一掃できるようになる」を毎回見せるか、「もう見なくていい」で飛ばすかは **［未決］**です。
> 私の推しは**両方**：初回は一掃する絵を見せ、2回目以降はスキップできる。

### 変更点3：**転生を重ねるとプレイスタイルが変わる**

| 転生回数 | 変わること |
|---|---|
| 1回目 | 換装が出る。恒久ツリーが開く |
| 2回目 | シナジーが出る。編成の組み合わせを考え始める |
| 3回目 | デッキ編集。3択の中身を自分で決める |
| 5回目 | **階層を2つ飛ばして開始**できる |
| 10回目 | **自動出撃**（放置の入口）**［未決］** — 入れるかどうか |

## 転生の動機を3つ用意する［仮説］

1. **速くなる**（恒久ツリー）— 測れる目標：speedup 3.0倍
2. **新しいものが出る**（換装・シナジー・デッキ）
3. **奥へ行ける**（階層）

今は 1 が機能しておらず、2 と 3 が存在しません。**3つとも要ります。**

# 8. 設計上の矛盾と、実装前に検証すべきリスク

## 矛盾

### 矛盾1：**「大量の敵」と「既存マップ」は両立しません**［実測］

- 通路が2タイル幅なので、入る敵の上限が **258〜437体**
- 600体を出しても、残りは出現口に溜まって画面に出ません
- **敵数を増やす設計は、マップ改修とセットでしか意味を持ちません**

### 矛盾2：**「段階解放」と「3択の成立」は衝突します**

- 今は所持カード全部が抽選に入ります
- 序盤に絞ると候補が2〜3枚になり、**3択が選択になりません**
- **対策案**：序盤は「同じカードの2枚目・3枚目」を候補に混ぜる（重ねがけ）。
  今の `stackLimit` と `cardWeight` の仕組みでそのまま作れます

### 矛盾3：**「置く楽しさ」と「放置」は相反します**

- 陣地を設計するのが本体なら、自動出撃はその楽しさを飛ばします
- インクリメンタルの定番ではありますが、**入れるなら「一度クリアした階層だけ」**に限るべきです

## リスク（実装前に測るべき順）

| 優先 | リスク | 測り方 | 今わかっていること |

## 実装の順番（提案）［仮説］

数字を決める前に、**構造**を決める必要があります。

```
① 転生の作り直し（恒久ツリー＋進行を戻さない）
      ↓  ここで speedup 3.0 を実測で確認する
② 階層制の骨組み（敵数と敵HPを階層で分ける）
      ↓  ここで実機のfpsを測る
③ マップを階層に合わせて広げる
      ↓
④ 解放順の実装（1回に1つ）
      ↓
⑤ 数値の詰め（ここで初めてバランス調整）
```

**①が終わるまで、既存のバランス値は触りません。**
