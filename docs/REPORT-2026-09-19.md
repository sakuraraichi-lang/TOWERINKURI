## 1. 作っているもの

**インクリメンタル × ローグライト × タワーディフェンス × カード構築**の Web ゲーム。

- HTML5 Canvas + 素の JavaScript。ビルド工程なし、`<script>` 直書き
- スマホで遊べる。公開先は Vercel の予定
- リポジトリ: `https://github.com/sakuraraichi-lang/TOWERINKURI`

### コアループ

```
敵を倒す → コイン / カード
   ↓                ↓
スキルツリー      カード
(数字を大きくする) (武器の挙動を変える)
   ↓                ↓
   └──→ ウェーブ進行 → ステージ突破 → カードパック → 転生 ──┘
```

## 2. 開発方針

### いただいた方針（これに従っています）

- **まず遊べる状態にする。** 30分以上かかる機能は簡略化
- **インフレも、後半が楽になることも、過去コンテンツの陳腐化も「正常」。** 不具合ではない
- **絶対値でなく比率で判断する**（敵HP ÷ プレイヤー期待DPS）
- **初見突破率を先に決め打ちしない**
- **先に実データを観測する**
- **調整可能なパラメータを一箇所に集約する**（← 今回やりました）
- **完璧なバランスより先に「調整できる仕組み」を作る**
- **標準 / 強力 / 非効率 の複数ビルドで試す**
- **強ビルドを即ナーフしない**
- 敵ステータスは 基礎値 × ウェーブ係数 × 敵固有係数
- **難易度について抽象的な議論を続けない**

### 私が自分に課しているルール

- **自己申告の数字を信用しない。** `tools/sim.html` で実測してから言う
- **測定器を先に疑う。** 直近、これを怠って誤った結論を報告しました（後述）
- **旧結論を否定したら、README も直す。** チャットの訂正だけで終わらせない

## 3. 今回やったこと

### (a) スキルの効果量を一箇所に集約した（`00bf2d4`）

倍率（×1.11 など16個）が**説明文と計算式の両方にベタ書き**されていて、片方だけ直すと表示と実効果がズレる状態でした。

各スキルが `eff`（効果量）と `tmpl`（`{e}` を `eff` で埋める説明文）を持ち、表示も計算も同じ `eff` から作る形にしました。カテゴリ倍率は定義から自動で組み立てるので、ノードを足しても `mods()` を触る必要がありません。

リファクタ前と**全19項目で数値が一致**することをブラウザ実測で確認済み。

### (b) 測定器に3つ欠陥が見つかり、全部直した（`06c7d6d`）

| 欠陥 | 何が起きていたか |
|---|---|
| 自動配置が通路に張り付いていた | 候補が「通路に隣接するタイル」だけ。射程430のスナイパーと射程100の刀が同じ場所から撃っていた。**射程差が測定上まるごと消えていた** |
| 「強力」と「標準」が同じ編成だった | 武器4種が完全に同一で順番違い。同じものを2回測っていた。「非効率」も2種しかなく「射程が短い」と「種類が少ない」が混ざっていた |
| 打ち切りを「失敗」と数えていた | 時間上限を超えると、倒せていても失敗扱いで15回やり直していた |

## 4. 報告したいこと（実測）

### ① ビルド差の逆転は「ゲーム側」ではなく「測定器側」の問題でした

旧配置を `autoPlaceHug` として残し、**同じ条件でA/B**を取りました。

| ビルド | 旧配置（通路に張り付き） | 新配置（射線で選ぶ） |
|---|---|---|
| 標準（射程を散らす） | 5/5 … 1, 5, 5, 2, 3 | **5/5** … 1, 4, 3, 1, 2 |
| 強力（シナジー狙い） | 2/5 … 1, 4, 打切 | 2/5 … 1, 5, 打切 |
| 範囲・支援寄り | 2/5 … 1, 3, 未突破 | **5/5** … 1, 2, 2, 1, 1 |
| 非効率（短射程だけ） | 1/5 … 1, 打切 | 2/5 … 1, 1, 打切 |

**「非効率な編成がいちばん強い」は再現しません。** 新配置では順当に、標準と範囲・支援が全ステージを抜け、短射程だけの編成は2ステージで止まります。

### ② 【本命】ウェーブの9割が「敵が出てくるのを待っているだけ」の時間

「削る秒数」＝敵の総HP ÷ 実測DPS。「湧き秒数」＝最後の1体が湧き終わるまで。

| 通算W | 削る秒数 | 湧き秒数 | 実際の秒数 | 比 |
|---|---|---|---|---|
| 1 | 7.3s | 7.0s | 18.0s | 拮抗 |
| 6 | 23.4s | **29.7s** | 38.7s | 1.3倍 |
| 11 | 28.4s | **54.1s** | 59.3s | 1.9倍 |
| 16 | 22.3s | **77.2s** | 84.0s | **3.5倍** |
| 20 | 14.9s | **71.8s** | 80.8s | **4.8倍** |
| 25 | 45.8s | **61.6s** | 65.7s | 1.3倍 |

- 通算W6で湧きが削りを追い越す
- **1周（全5ステージを1回ずつ突破）で約24.5分。** ステージ別に 1.7 / 4.7 / 5.4 / 6.9 / 5.8 分
- **原因の半分は敵の設定ではなく `敵誘引` スキル。** 基本の敵数は通算W16で168体ですが、実測は571体。差の**×3.4が敵誘引**です（安い順に買うと自然に積み上がる）。「敵が増えてコインも増える」スキルが、そのままウェーブの長さになっている

### ③ 敵数の上限600は、今のところ実害が小さい

通算W17から効き始め、W25では966体のはずが600体（**38%抑制**）。ただし削る秒数は全体で22〜50秒の帯に収まっており、ステージHP係数（×1.35^ステージ）が相殺しています。

### ④ 訂正

以前「要る秒数が 45.4s → 11.5s に落ちる」と報告しましたが、**あれは旧配置＋打ち切り誤判定の条件で出た数字で、再現しません。** README にも訂正として明記しました。

もうひとつ、以前「スキル価格を上げても効かない」と報告し、その後の実測で**ご指摘のほうが正しく私の結論が誤り**だったことを確認しています（到達時の総段数 252 → 99、火力 ×11.5 → ×2.7）。

## 5. 悩んでいるところ（判断を仰ぎたい）

### (A) ②をどう直すか ＝「1ウェーブを何秒にしたいか」

ここはゲームのテンポそのものを決める設計判断なので、私では決められません。数字を3案出します（表の値は**湧き切る秒数**）。

| 通算W | 現状 | 案1 減衰 0.97→0.94 | 案2 案1＋基準 0.22→0.16 | 案3 敵誘引 0.12→0.05 |
|---|---|---|---|---|
| 1 | 7s | 7s | 5s | 7s |
| 5 | 16s | 14s | 10s | 14s |
| 16 | **77s** | 47s | **34s** | 45s |
| 20 | **72s** | 38s | **28s** | 54s |
| 25 | **62s** | 28s | **21s** | 56s |

- **案1** … 序盤は今のまま、後半だけ縮む。安全側
- **案2（私の推し）** … 案1に加えて全体も少し詰める。W16で削り22秒に対し湧き34秒と、ようやく同じ桁になる
- **案3** … 敵誘引の倍率を下げる。「敵を増やす」スキルの性格は残るが、時間の肥大は直接には止まらない

**案2を推す理由:** 測って良かった帯（通算W1〜5は湧き7秒 / 削り7秒で拮抗）を壊さず、壊れている後半だけを詰められます。案3は敵誘引という**プレイヤーの選択**を弱めることになるので、先に敵側の設定で直すほうが筋が良いと考えます。

### (B) 「強力（シナジー狙い）」が3ステージ目で止まる

触手＋ミサイル（伝説）／触手＋迫撃砲（叙事詩）／ミサイル＋テスラ（叙事詩）が同時に狙える編成が、**新旧どちらの配置でも2/5 止まり**です。

ただしこれは「打ち切り」で止まっており、②が直らないと測定自体が通りません。**②の後に回します。** シナジーが実は弱いのか、測定が届いていないだけなのか、今は区別できません。

### (C) 自動配置は「人の手」の代わりになっていない

新配置は「扇の中にどれだけ通路が入るか」で場所と向きを決めますが、**人が考える十字砲火・射線の重ね方は再現できていません。** 実測は「下手なプレイヤー」の値だと思ってください。

**ここは実際に遊んでいただくのがいちばん確かです。** 私の数字と体感がズレていたら、体感のほうが正しいです。

### (D) マップの規模

参考にされているゲームは、もっと大きく斜めの多いマップに見えます。今は 15×21 です。**大きくするかどうかは設計判断なので、指示待ちにしています。**（勝手に着手していません）

## 7. 詰まっていること（環境）

**`git push` がこの環境から実行できません。**

- `git ls-remote origin` → exit 0（読みは通る）
- `git push -u origin main` → **認証入力を待って2分ハング**（この環境では対話入力ができない）
- `credential.helper` が `manager`（対話認証必須）、`gh` コマンドも未インストール

**そして GitHub 側のリポジトリは現在ブランチが1つもありません**（`git ls-remote --heads origin` が空）。つまり**ローカルの23コミットは1本も上がっていません。**

お手元で以下を実行していただく必要があります。

```
git push -u origin main
```

これが通れば Vercel の Import に進めます。
