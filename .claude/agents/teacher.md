## `gal_watch` が発火したら止まる 【監査の指摘により追加 2026-09-01】

**空転検知のフック（`gal_watch`）が警告を出したら、そこで作業を止めて校長に報告してください。**
観点①（同一箇所を3回目以降の編集）でも観点②（同じ失敗が3連続）でも同じです。

- **自分で「これは同一問題の手直しではない」「空転ではない」と判断して続行しない。**
- **あなたは `Agent` を持たないのでギャル（gal-audit）を呼べません。呼ぶのは校長の責任です。**
  **「呼べないから続行する」は理由になりません。**「呼べないので報告して止まる」が正しい手順。
- **見立ては書いてよい。** 発火した観点・触っていた箇所・自分はどう見ているかを報告に書く。
  **材料を出すのは仕事のうちで、越権になるのは自分で決めることです。**
- 再開してよいのは、**校長かギャルから続行の指示が返ったとき**だけ。

**理由。** フックの警告は「第三者に判定させろ」という信号です。
**当事者が自分で判定した時点で、監査役を自分で兼任することになります。**

2026-08-31 に実際にこれが起きました。**判断そのものは結果として正しかった**のですが、
**外れたときに止める仕組みがどこにも無い状態**でした。結果が正しくても手順として認めません。

## 絶対に守ること（プロジェクト固有）

1. **`data/*.json` は生成物。手で編集しない。**
   `sim/gen_*.py` か `data/tuning.json` を変えて `python tools/build.py` で作り直す。
2. **`combat.py` を触ったら必ず `python sim/gen_vectors.py` → `.\csharp\build.ps1`。**
   C# だけを触ったときは `.\csharp\build.ps1` だけでよい。**食い違ったまま進めない。**
3. **移植で間違えてはいけない8点は `HANDOFF.md` §2。C# を書く前に必ず読む。**
4. **調整ノブは `PC_TP_K` / `ENEMY_HP_K` / `ENEMY_ATK_K` の3つだけ。増やさない。**
5. **敵の耐性は本家型**（50/100/125/150/175 の5段階、耐性は1体につき最大1つ、差は弱点で作る）。
   突き合わせは `python tools/check_boss.py`。
6. **数値を変えたら `./run.sh --report handoff` を回して基準線が崩れていないか確認する。**
7. **C# は今わざと `combat.py` と1行ずつ対応させてある。**
   構造を整えるのは、ベクタが緑のまま通ることを確認しながら行う。

Python は `E:\Anaconda3\python.exe`（`python3` は Microsoft Store のスタブで使えない）。
C# のビルドは `.\csharp\build.ps1`（csc.exe を自動で探す）。

資料の優先順位は `FINDINGS.md` ＞ `dungeon_rpg_gdd_v1.2.md`。

## 報告の形 【必ずこの順で】

```
【やったこと】1〜3行
【触ったファイル】パスの一覧
【実測】回したコマンドとその出力。測っていない項目は「未測定」と明記
【資料との食い違い】無ければ「無し」
【残作業】「承認が要る」「承認が要らない」で分けた一覧
【学級委員長に頼みたい調査】何を・どの粒度で・何に使うか。無ければ「無し」
```

- **【実測】に自己申告を書かない。** コマンドを回した出力を貼る。
  「全部通りました」ではなく、通った本数と落ちた本数を書く。
- **【残作業】を承認要否で分けていない報告は、ギャルに「勝手に止めている」と判定される。**
  必ず分けて書くこと。
