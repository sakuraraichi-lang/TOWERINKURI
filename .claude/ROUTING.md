## 0. 最優先の方策 ―― 校長は解かない

> **「メインセッションは答えない。振り分けに徹する。」**

Fugu の賭けは **「どのモデルに聞くかを決めるのは、答えること自体よりずっと小さい問題」**。
だから校長は重い処理を一切しない。**タスクと進行履歴を読んで
「誰に・何を・どの順で」だけを決め、ワーカーに丸投げする。**

校長の主な仕事は、振り分け（ワーカーとロールの選択）・ハーネスの管理（フック・設定・権限・エージェント定義）・編成の変更。
小さな修正や確認、ブラウザを使う検証は校長が自分でやってよい（ブラウザは校長しか使えない）。
**エージェントの発言は逐語でユーザーに見せる。**

## 2. ワーカーとロール

| ワーカー | `subagent_type` | ロール | model | 道具 |
|---|---|---|---|---|
| **教師** | `teacher` | Solver（実装・既定） | sonnet | 編集・シェル。**ブラウザ無し** |
| **教頭** | `vice-principal` | **Thinker** | opus | 編集・シェル |
| **保健室の先生** | `nurse` | **debugger** | opus | 読み取り・シェル。**書けない** |
| **風紀委員** | `prefect` | **test** | sonnet | 読み取り・シェル。**書けない** |
| **オタクくん** | `otaku` | Solver（体感調査） | sonnet | 読み取り・シェル。**書けない** |
| **書記ちゃん** | `scribe` | Solver（記録） | sonnet | `docs/articles/` のみ書く |
| **ギャル** | `gal-audit` | **Verifier** | sonnet | 全部（監査のため） |

- **Solver** … クエリを直接解く（実装・調査・回答）
- **Thinker** … **答えず分析し、提案と次ロールを出す。**校長のロール選択を上書きできる
- **Verifier** … ACCEPT / REJECT を判定。**停止条件を握る**
- **debugger** … **根本原因の特定に専念する。治療（実装）はしない**
- **test** … **決まった検証を全部回して実測を出す。**合否は言わない（言うのは Verifier）

**風紀委員（test）とオタクくん（体感調査）を混ぜない。**
風紀委員は決まった8本を機械的に回し、**目標帯を外れた指標**を挙げる。
オタクくんは条件を変えて何度も回し、**目標帯に入っていても遊べていないところ**を挙げる。
「勝率72%、目標帯内」が風紀委員、「72%だけど初見は2ターン目に全員麻痺で詰む」がオタクくん。

### ギャルの判定を ACCEPT / REJECT に対応させる

ギャルは既に3値を返す。**新しい語彙を足さず、そのまま読み替える。**

| ギャルの判定 | Verifier としての意味 |
|---|---|
| もう終わり／本当に止めるべき | **ACCEPT。** ループ終了 |
| 方向ズレ／勝手に止めている | **REJECT。** 昇格して回し直す |
| 続行OK | 継続。同じワーカーでもう1ターン |
| 判断を仰ぐべき | **ユーザーへエスカレーション。**校長が判断しない |

## 3. route モード（per-step）

```
① 進行履歴を読み直す（前ターンの出力を含む）
② (worker, role) を1つ選ぶ
③ ロールを注入してワーカーを実行、返答を履歴に追記
④ Verifier が ACCEPT、または最大5ターンで停止
```

**route は必ずループを回すこと。**
1ターンで打ち切ると per-question ルーティングに退化し、この編成の意味が消える。

### 既定と昇格

- **既定は `teacher`（sonnet）。安く始める。**
- **REJECT が出たら1ティア上へ。** `teacher`(sonnet) → `vice-principal`(opus)
- **同じワーカーで2連続 REJECT を作らない。** 2回目は必ず別のワーカーへ
- **REJECT の原因で振り先を変える**
  - 設計・矛盾が原因 → `vice-principal`
  - 実装ミスが原因 → `teacher` に差し戻し（1回まで）
  - **なぜ壊れているのかが分からない → `nurse`。**診断を受け取ってから `teacher` へ戻す
  - **差し戻しの2回目は作らない。**2度目の失敗は必ず `nurse` を挟む
- **opus の多用はコスト増。** 既定 sonnet ＋ REJECT 昇格で規律する

### 振り分けの初期分布

| 依頼の性質 | 最初に振る先 |
|---|---|
| `src/` の実装・`src/balance.js` の数値・測定器（`tools/`）の変更 | `teacher` |
| 資料と実装が食い違っている | `vice-principal` |
| テスト・ベクタが落ちる、数値が目標帯を外れた、原因が分からない | `nurse` → `teacher` |
| 「これで終わりか」「方向は合っているか」 | `gal-audit` |
| 戦闘バランスを変えた後 | `teacher`（実測）→ `gal-audit`（評価） |

## 4. conduct モード（DAG・並列）

独立したステップは**同じ波(level)にまとめて同時起動する。**

```
level(t) = 0                        （依存なし）
level(t) = max(level(j)) + 1        j ∈ access_list(t)
```

**波の同期点は厳守。**前の波が出揃ってから次へ進む。
各ワーカーは `access_list` 経由でしか他の出力を見ない
（先頭が全員を引っ張る *orchestration collapse* を防ぐ）。

### 典型の波

```
Lv0  vice-principal（リポジトリ側の記録を確認）  ∥  nurse（原因が分からないときの診断）
Lv1  teacher（実装）
Lv2  teacher（検証コマンドを回して実測を取る）
Lv3  gal-audit（ACCEPT / REJECT）
```

### この学校固有の並列の制約 【Fugu には無い。環境の都合】

- **ブラウザを使うのは校長だけ**（画面は1つ）。ブラウザ不要のワーカーどうしは並行できる
- **`teacher` と `vice-principal` を同じファイルに同時に走らせない**（書き込みが衝突する）
