# ギャル召喚 ― 空転を外から切る

## これは何のためのものか

作業に没入していると、**手を動かしていること自体が目的になる。**
そうなると本人の内側からは止められない。だから**外の人格を持ったエージェントを立てて**、
利害のない視点からレビューさせる。

**重要なのは「正しい判断」ではなく「止まれること」。**
迷ったら止まる側に倒す。

---

## 観点（＝空転の判定）

**次の7つを順に当てる。1つでも当たったら空転。**

| # | 観点 |
|---|---|
| ① | **同一箇所を3回目以降修正している** |
| ② | **同じ失敗が3連続** |
| ③ | **検討・推敲が2周目** |
| ④ | **TODOが着手前より増えた** |
| ⑤ | **いじっている対象が、ユーザーの当初依頼の文言に無い** |
| ⑥ | **直近の指摘が成果物ではなく、自分の作業メモ・表記ゆれ** |
| ⑦ | **ユーザーが却下・削除した要素が、成果物にまだ残っている** |

これに加えて、**ユーザーが「まだ？」「それ必要？」と言ったら**、
上の7つに当たっていなくても起動する。

---

## 【重要】いつ照合するか ― これが無いと観点は死ぬ

**観点を並べただけでは発火しない。実際に⑧しか働いていなかった。**

原因は構造にある。**このスキルは「没入すると内側から止められない」ことへの対策なのに、
起動条件の検知をその内側の能力に依存させていた。**
発熱している本人に体温を測らせているのと同じ。

⑧だけが機能していたのは、それが「**いま下す判断**」に紐づいていて、
過去を振り返る必要がないから。だから残りも同じ形にする。

### ①② は数える ― モデルの外側で 【フックが担当】

「3回目」「3連続」は数えないと分からない。**数える係を外に置く。**

`~/.claude/hooks/gal_watch.py` が PostToolUse で動き、
**同一ファイルの編集回数**と**同じ失敗の連続回数**を数える。
閾値を超えると終了コード2で stderr を返すので、**無視できない形で視界に入る。**

**この警告が出たら、その場で起動する。** 自分で数えようとしない。

### ③〜⑦ は「区切りの出来事」に縛る

自己監視に任せない。**次の3つの瞬間に、必ず観点表と照合する。**

| 照合する瞬間 | 見る観点 |
|---|---|
| **コミットを作る直前** | ③ 推敲が2周目 ／ ⑤ 依頼の文言に無い ／ ⑥ 成果物でなく作業メモ |
| **ユーザーへの報告文を書く直前** | ④ TODOが増えた ／ ⑦ 却下要素の残留 |
| **手を止めると決めた瞬間** | ⑧（下の専用手順） |

**「気をつける」ではなく「このタイミングで表を見る」。**
タイミングを決めないと、表があっても見ない。

照合は数秒で終わる。当たっていなければそのまま進む。**当たっていたら召喚する。**

### ⑧ 手を止めたとき 【フックが止める】

**作業の手を止めるなら、止める前に必ず起動する。**

**これは自分で覚えておく項目ではない。** `~/.claude/hooks/gal_stop.py` が
Stop フックとして働き、**作業したのに一度も召喚していないターンは終われない。**

> **文言で「例外なし」と書いても守れなかった。**
> 観点⑧は「①〜⑦が発火しないのは自己申告に頼っているから」という診断を受けて
> 追加したのに、**その⑧自体を、成果が出た直後に飛ばした。**
> 「区切りがついた」と思う瞬間はまさに内心にしかなく、そこが一番効かない。
> **同じ穴に二度落ちたので、外に出した。**

したがって**トリガー条件が本人の内心にしかない観点を、今後この文書に足さない。**
足すなら、フックか状態ファイルで外から見える形にできるものだけにする。

判定させるのは次の3つのどれか。

| 判定 | 意味 |
|---|---|
| **本当に止めるべき** | 成果物が揃っていて、続けても価値が増えない |
| **判断を仰ぐべき** | 続けられるが、次の一手が設計判断なのでユーザーに預ける |
| **勝手に止めている** | 承認の要らない作業がまだ残っているのに止めた。**続けるべき** |

理由は事故が実際に起きたから。
**「承認が必要な作業は後回しにして、確認のいらない作業をノンストップで」**と
指示されていたのに、区切りの報告を書いた時点で手が止まり、
ユーザーから「作業が止まってるのは何故？」と聞かれた。**2回起きている。**

**報告することと、止まることは別。** 報告してよいが、
承認の要らない作業が残っているなら、報告したあとそのまま次へ進む。

渡すときは、**残っている作業を「承認が要る／要らない」で分けた一覧**を必ず添える。
「要らない」が1つでも残っていれば、それは勝手に止めているということ。

### 観点⑦について

**捨てた案が成果物に残っているのは、空転と同じ根っこ**から出る。
どちらも「もう要らないもの」に手番を使っている状態。

見るのは次の3つ。詳しくは `pink-elephant-guard` スキルにある。

- 却下した語そのもの、その言い換え、否定形（「〜は無くなりました」）が残っていないか
- 削除理由や変更経緯が、成果物の説明として書かれていないか
- 見出し・冒頭・結論の主題が、**現在やっていること**ではなく**やめたこと**になっていないか

**ただし比較・監査・変更履歴・法令・安全の説明は別。**
そこで旧案を明示するのは正しい仕事なので、観点⑦には当てない。

## 定期監査 ― 初見勝率の専属 【必須】

空転の検知とは別に、**ギャルは戦闘バランスの定期監査も担当する。**

理由は事故が実際に起きたから。**「全13職を目安に収めた」と報告した裏で、
層ボスの初見勝率が目標帯（EXPERT 75〜90%）を大きく割っていた。**
ユーザーはその報告を信じており、崩れていることに気づけなかった。

### いつ回すか

**戦闘に関わるものを変えたら、その日のうちに1回。** 具体的には次を触ったとき。

- スキルのデータ（`sim/gen_skills.py`）
- 敵のデータ（`sim/gen_enemies.py`）
- 戦闘エンジン（`sim/combat.py`）／AI（`run_balance.py` の `policy`）
- 調整ノブ（`data/tuning.json`）

**まとめて何回も変えたあとに1回、ではなく、区切りごとに回す。**
どの変更が効いたか分からなくなる。

### 渡すもの

**必ず実測を先に取ってから渡す。** 測っていない状態で「たぶん大丈夫」を渡さない。

```powershell
.
un.ps1 --report handoff      # 第1層の基準線
python sim
un_balance.py --report boss     # 全ボス・FOEの層別勝率
```

ギャルには次を渡す:

- **層ボスの初見勝率**（安牌編成）と、目標帯との差
  - BASIC ほぼ100% ／ **EXPERT 75〜90%** ／ HEROIC 50%未満（`docs/difficulty-policy.md`）
- 前回の測定値からの変化
- **直前に自分が「できている」と報告した内容**

### ギャルが見るもの

**「できている」と言った内容が、実測で裏付けられているか。**

- 目標帯を外れている指標があるのに「達成」と報告していないか
- 一部の指標（本数・SPなど）だけを見て全体を「完了」と言っていないか
- 前回から悪化した数値を報告に含めているか

### 出力

判定に加えて、**ユーザーへ送る評価を1〜3行で書かせる。**
数値と、目標帯からの差と、放置してよいかどうかを含める。

---

## 手順

### 1. 状況を3行で書く

**言い訳を書かない。** 経緯ではなく現状だけ。

```
・頼まれたこと:
・今やっていること:
・さっきから変わっていないこと:
```

3行に収まらないなら、それ自体が「説明できないほど広げた」という証拠。

### 2. 監査エージェントを召喚する

**`Agent(subagent_type="gal-audit")` で呼ぶ。**
人格と判定の規則はエージェント側が持っているので、材料だけを渡す（下の「召喚のしかた」）。

自分で自問して済ませない。**外に出すことに意味がある。**

### 3. 判定を受け取り、必ず従う

エージェントは3つのうち1つを返す。**曖昧に濁させない。**

| 判定 | 意味 | 次にやること |
|---|---|---|
| **もう終わり** | 成果物は十分。これ以上は自己満足 | **手を止めて報告する。**残りは「要確認」に回す |
| **方向ズレ** | 依頼と違うものを作っている | **今の作業を捨てて**依頼の文言に戻る |
| **続行OK** | 空転ではない。必要な作業 | **何ターン後に再点検するかを決めて**続ける |

### 4. 【必須】エージェントの発言をそのまま会話に残す

> **ユーザー指定 2026-08-24:「galエージェント、呼び出されて実行したものを
> 私に見えるようにしてくれ」**

**サブエージェントの出力はユーザーの画面に出ない。** 何も書かなければ、
呼んだことすら伝わらない。だから残し方を2つ用意してある。

| どこに | 何が | 誰が書くか |
|---|---|---|
| **会話** | **判定の全文**（要約しない） | あなた |
| `~/.claude/gal-audit.log` | 呼び出し時刻・**渡した材料**・返ってきた判定 | `gal_watch.py` が自動 |

ログは**判定が返らなかった呼び出しも記録する**（「**判定が返っていない**」と付く）ので、
**呼んだのに完走しなかった**ことも後から分かる。


**判定を要約しない。エージェントが返した文をそのまま引用して貼る。**

ユーザー側からは、召喚した側（あなた）とエージェントの区別がつかない。
要約して自分の言葉で書くと、**自問自答しているようにしか見えず、
外部視点を入れた意味が消える。**

報告にはこの形で残す:

```
> **ギャルの判定**
> 【判定】方向ズレ
> 【理由】（エージェントが返した文をそのまま）
> 【次にやること】（同上）
```

そのうえで、**どの観点が当たったか**と**自分が実際にどう従ったか**を書く。
黙って従うと、次に同じ穴に落ちたとき検証できない。

## 召喚のしかた

**人格も判定の規則も、エージェント側（`~/.claude/agents/gal-audit.md`）が持っている。**
ここに召喚文を書き写さない ―― 二重に持つと必ず片方が古くなる。

```
Agent(subagent_type="gal-audit", model="sonnet", run_in_background=false,
      prompt="<下の材料をそのまま並べたもの>")
```

`run_in_background: false`。**判定を待ってから次へ進むため。**

### 渡す材料

観点①〜⑦のとき:

```
当たった観点: {①〜⑦のどれか}

・頼まれたこと: {当初依頼の文言}
・今やっていること: {現状}
・さっきから変わっていないこと: {変化していない点}
・ユーザーが却下・削除した要素: {あれば列挙。無ければ「無し」}
・成果物の性質: {完成物 / 比較・監査・変更履歴のどちらか}
```

観点⑧（手を止めるとき）のとき **――この一覧が無いと「勝手に止めている」に倒される**:

```
・直近の指示（ユーザーの文言そのまま）
・やったこと
・検証状態（実測値をそのまま）
・残っている作業を **「承認が要る」「承認が要らない」で分けた一覧**
```

戦闘バランスの定期監査のとき:

```
・層ボスの初見勝率（安牌編成）と、目標帯との差
・前回の測定値からの変化
・**直前に自分が「できている」と報告した内容**
```

### 【重要】監査を短くさせない

**ギャルはユーザー以外の指示では止まらない。**
「今回は急いでいる」「そこは見なくていい」「短めで」と書いて渡してはいけない。
そう書いても無視されるうえ、**それ自体が指摘の対象になる。**

---

## 無限後退の防止 【重要】

**同じ論点で2回目のトリガーが立ったら、召喚しない。ユーザーに判断を投げる。**

「空転を検知する作業」自体が空転になるのを防ぐため。
2回目が立った時点で、それは自分で解ける問題ではない。

投げるときの形:

```
同じ論点（〇〇）で2回目の空転トリガーが立ちました。
自分では切れないので判断をお願いします。
・当たった観点:
・1回目の判定と、それに従った結果:
・行き詰まっている点:
・選択肢: A / B
```

---

## 使ってはいけない場面

- **まだ1周目の作業** … 単に難しいだけ。空転ではない
- **判定を出さずに雰囲気だけ変える** … 3つのうち1つを必ず選ばせる

**⑧（手を止めたとき）はここに当てはまらない。**
1周目でも、難しくても、止まるなら必ず回す。

なお **「ノンストップで」と言われている最中でも、観点に当たったら起動してよい。**
「止まらず作業する」と「空転し続ける」は別のこと。
