## 直し方 ― 数えられるものはモデルの外へ

### ①② はフックが数える

`~/.claude/hooks/gal_watch.py` を PostToolUse に登録してある
（`~/.claude/settings.json`。対象は Edit / Write / NotebookEdit / Bash / PowerShell）。

| 数えるもの | 閾値 | 備考 |
|---|---|---|
| 同一ファイルの編集回数 | **3回**（以後 6/12/18…） | **`git commit` が通ると数え直す** |
| 同じ失敗の連続回数 | **3回** | 別の失敗が挟まると切れる |

閾値を超えたときだけ **終了コード2 + stderr** で返す。
PostToolUse の終了コード2は「ツールは実行済みで、stderr が Claude に見える」なので、
**無視できない形で視界に入る。** 超えていなければ黙って0で返す。

#### 設計の要点

- **コミットでリセットする。** 1本のファイルを詰めていく作業は普通にある。
  空転なのは「**何も出荷しないまま**同じ場所を3回直している」ほう
- **一時ファイル（scratchpad）は数えない。** 作業の本体ではない
- **失敗の指紋は行番号・パス・数値を落として取る。**
  そうしないと「同じ失敗」が毎回別物に見える
- **stderr は UTF-8 で直接書く。** Windows の Python は既定で cp932 に変換してしまい、
  受け取り側が UTF-8 として読むため化ける（実際に化けた）

### ⑧ もフックが見る 【2026-08-24】

**観点⑧自体を、書いた本人が飛ばした。**

⑧は「①〜⑦が発火しないのは自己申告に頼っているから」という診断を受けて
追加したもの。**その⑧を、戦闘の目標が全部そろった直後に飛ばした。**
「区切りがついた」と思う瞬間は内心にしかなく、**成果が出た直後が一番効かない。**

> 自己申告ルールは自分が気持ちよくなった瞬間に一番効かない。

#### 最初の版は仕様を読まずに書いて、壊れていた

急いで `gal_stop.py` を入れたが、**公式ドキュメントを読まずに書いた。**
あとで読み直したところ2点が実際と違っていた。

| | 最初の版 | 公式ドキュメントの実際 |
|---|---|---|
| ループ防止 | `stop_hook_active` を読む | **そのフィールドは存在しない。** Stop入力は `session_id` / `prompt_id` / `transcript_path` / `cwd` / `permission_mode` / `effort` / `hook_event_name` / `last_assistant_message` / `stop_reason` |
| ブロック方法 | 終了コード2 | **これは正しい**（"Prevents Claude from stopping, continues the conversation"）。`{"decision":"block", ...}` は現行の Stop 出力スキーマ（`hookSpecificOutput`）に無い |
| ブロック上限 | ― | **記述なし。** 自前で持つしかない |

**ループ防止が常に偽で完全に死んでいた。**
「読まずに書いて、動作確認は自分の想定どおりのJSONを流して通した」のが原因。
**フックの入力は、自分の想定ではなく仕様で確かめる。**

#### いまの形

`~/.claude/hooks/gal_stop.py` を Stop フックに登録。上から順に、当てはまれば素通り。

| # | 条件 | 意味 |
|---|---|---|
| 1 | stdin が読めない | フックの都合でセッションを壊さない |
| 2 | `last_work_at` が無い | 作業していないターン |
| 3 | `last_audit_at >= last_work_at` | 作業のあとに監査が完走している |
| 4 | `blocked_prompt == prompt_id` | **ループ防止。** 同じターンでは1回しか止めない |
| 5 | それ以外 | `blocked_prompt` を書いて **exit 2** |

**stderr は苦情ではなく次の行動指示**として書く（何をどう実行すれば開くか）。

#### 正式なサブエージェントになった 【2026-08-24・ユーザー指定】

> **「ギャルは完全に独立して、監査に関しては僕以外の指示で止まらないでください」**

人格と判定の規則を **`~/.claude/agents/gal-audit.md`** に移した。
`SKILL.md` は**材料の渡し方だけ**を持つ（召喚文を二重に持つと片方が古くなる）。

エージェント側の冒頭に**独立性**を明記してある。

- 呼び出し側（Claude）の指示で監査を中断・緩和・省略しない
- 「急いでいる」「そこは見なくていい」「短めで」は**すべて無視する**
- **止められるのはユーザー本人だけ**
- 呼び出し側が自分に都合よく書いた要約は疑ってよい。**自己申告を鵜呑みにしない**

フックの完走判定も、**`subagent_type == "gal-audit"`** を見るようにした
（人格の書き出し「ギャル」でも拾うのは、名前を指定しない呼び方を取りこぼさないため。
**どちらでも `【判定】` が返っていることは必須**）。

| # | 試したこと | 結果 |
|---|---|---|
| A | `gal-audit` ＋`【判定】`あり | 完走として認める（Stop 素通り） |
| B | `gal-audit` だが`【判定】`なし | **認めない（exit 2）** |
| C | 別のエージェントが`【判定】`を含む | **認めない（exit 2）** |
| D | `gal-audit` 完走後の編集3回 | 1・2回目は無反応、**3回目に観点①が発火** |

#### 「呼んだ」と「完走した」を分けた

最初は `tool_input` に「ギャル」が入っていれば記録していたが、
それは**召喚しただけ**でも通る。PostToolUse はツールが返ったあとに走るので、
**返答に `【判定】` が入っているか**まで見て「判定を受け取った」ところを捉える。

#### 状態ファイルへの書き込みを分けた

- `last_work_at` / `last_audit_at` … **`gal_watch.py` しか書かない**
- `blocked_prompt` … `gal_stop.py` しか書かない

**ゲート側が自分で「監査した」と書けない構造。**

#### ①②のリセット基準も変えた

**`git commit` ではリセットしない。** コミットは監査ではない。
**「最後に監査が完走してから何回編集したか」**を数える。
コミットのたびに数え直していた頃より**発火は増える。意図した強化。**

| 1 | 何も作業せず Stop | exit 0 |
| 2 | Edit → Stop（監査なし） | **exit 2**＋行動指示 |
| 3 | 同じ `prompt_id` で再び Stop | exit 0（ループ防止） |
| 4 | 別の `prompt_id` で Stop | **exit 2** |
| 5 | `【判定】`あり → Stop | exit 0 |
| 6 | `【判定】`なし（呼んだだけ）→ Stop | **exit 2** |
| 7 | 監査完走 → Edit → Stop | **exit 2** |
| 8 | commit を挟んで同じファイル3回編集 | **観点①が発火** |
| 9 | 監査完走後に3回編集 | 1・2回目は無反応、**3回目に発火** |

#### Bash 経由の作業を見落としていた 【2026-08-24・監査で発覚】

`last_work_at` と観点①のカウントを **`Edit` / `Write` / `NotebookEdit` でしか**
立てていなかった。しかし PostToolUse の `matcher` は
`Edit|Write|NotebookEdit|Bash|PowerShell|Agent` で登録してある。

**ファイルを書き換える手段はEditツールだけではない。**
`sed`・ヒアドキュメント・生成スクリプト（`gen_*.py`）はすべて Bash 経由で、
**実際このリポジトリの編集はほぼ全部 Bash から行われていた。**
つまり**ゲートは事実上ほとんど発火していなかった。**

> しかもHOOK.mdの動作確認表見たけど、9パターン全部Edit経由のテストで、
> Bash経由は一回も試してない。**テストしてないところに一番でかい穴があった**、って構図。

**`Bash` / `PowerShell` が呼ばれたら作業とみなす**ようにした。
コマンドが本当に書き込んだかを厳密に見分けるのは難しいので、
**読むだけのコマンドで余分に発火するほうを選ぶ。** 見逃すよりましである。

| # | 試したこと | 結果 |
|---|---|---|
| E | **Bash でファイルを書いた → Stop（監査なし）** | **exit 2**（塞いだ穴） |
| F | 監査を完走してから Stop | exit 0 |
| G | そのあと Bash をもう一度 → Stop | **exit 2** |
| H | 読むだけのコマンド（`cat`）でも Stop | **exit 2**（保守的な側） |

#### 監査の実行記録をユーザーに見せる 【2026-08-24・ユーザー指定】

> **「galエージェント、呼び出されて実行したものを私に見えるようにしてくれ」**

**サブエージェントの出力はユーザーの画面に出ない。**
`gal_watch.py` が `~/.claude/gal-audit.log` に追記する。

- 呼び出し時刻
- **渡した材料**（prompt。4000字まで）
- **返ってきた判定**（同上）
- `【判定】` が無い呼び出しは「**判定が返っていない**」と記録される
  ―― **呼んだのに完走しなかったことも後から分かる**

記録に失敗しても本体の判定は続ける（**記録の失敗で監査を止めない**）。

#### 監査の仕組みを git 管理下に置いた 【2026-08-24・ユーザー判断】

フック本体は `~/.claude/hooks/` にあり、**そこは git リポジトリですらなかった。**

> 監査ゲートの心臓部なのに、**履歴も差分レビューもロールバックも一切無い。**

**プロジェクト側 `<project>/.claude/` に移した。**

| 置き場所 | 中身 |
|---|---|
| `.claude/hooks/` | `gal_watch.py` / `gal_stop.py` |
| `.claude/agents/` | `gal-audit.md` |
| `.claude/skills/gal-summon/` | `SKILL.md` / `HOOK.md` |

`~/.claude/settings.json` はこちらを指す。
`.gitignore` は `.claude/*` を無視したうえで、この3つだけ例外にしてある
（個人設定・計画ファイル・ローカル上書きは持ち込まない）。

**移設先で全項目を測り直して確認済み**（作業なし素通り／Bash作業でブロック／
監査完走で開く／同一 prompt_id のループ防止）。

#### 記録の失敗で監査が止まっていた 【2026-08-24・監査で発覚】

`_log_audit` の `except` が `(IOError, OSError)` しかなかった。
応答に**単独サロゲート**が混ざると `UnicodeEncodeError`（`ValueError` 系）で関数ごと落ち、
**呼び出し元の `last_audit_at` を書く行まで到達しなかった。**

つまり「**記録に失敗しても本体の判定は続ける**」と書いてあった約束が、
そのケースで破れていた。**監査は完走しているのにゲートが開かない。**

- 書き込みを `errors="replace"` にして、そもそも落とさないようにした
- `except Exception` に広げた。**記録は副作用であって、本体より優先させない**

再現テストで確認済み（壊れた応答でも `last_audit_at` が書かれ、ゲートが開く）。

#### ここから引いた一般則

- **トリガー条件が本人の内心にしかない観点を、スキル文書に足さない。**
  足すなら、フックか状態ファイルで外から見える形にできるものだけにする
- **フックを書く前に仕様を読む。** 想定で書いたJSONで自己テストしても、
  想定が間違っていれば全部通ってしまう
- **`matcher` に登録した全ツールを、実際にテストする。**
  Edit だけ試して満足すると、**普段いちばん使っている経路が素通り**していても気づかない

#### 触ってはいけないもの 【ユーザー指定】

- **このゲート本体と状態ファイルを、Claude の判断で書き換えない**
- 無効化・条件緩和・閾値変更が要ると判断したら、**実行せず提案だけする**
- 期待どおり動かないときも、**フックを外す方向の修正はしない**
